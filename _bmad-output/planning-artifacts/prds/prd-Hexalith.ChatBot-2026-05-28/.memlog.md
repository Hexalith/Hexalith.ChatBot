- (decision) Hexalith.ChatBot is an email-first governed AI project workspace for B2B project teams because external collaborators already work through email and should not need another portal.
- (decision) The MVP proves one email-to-governed-action loop: capture authorized project email, resolve project context, govern attachments and task intent, approve risky AI work, execute through service commands, and audit the outcome.
- (decision) ChatBot owns orchestration and its security-sensitive derived records, while Projects, Parties, Folders, Tenants, EventStore, and mail integration retain authoritative source ownership; durable mutations use bounded-context commands and events.
- (decision) Project association gives deterministic evidence precedence over AI inference and fails closed into authorized evidence-based review whenever identity, scope, evidence, or confidence is unresolved.
- (decision) Tenant, actor, role, project, and resource authorization is enforced at command and query boundaries on every surface, and unauthorized projects or evidence are never disclosed.
- (decision) AI is a governed project actor: low-risk read-only assistance may run only under tenant policy, risky work requires authorized human approval, denied or unresolved requests are refused, and execution is limited to allowlisted commands.
- (decision) The first mailbox integration is a controlled Microsoft 365 or Exchange pattern using least privilege, and external participants remain represented as tenant-scoped Parties without authenticated portal access in the MVP.
- (decision) The MVP is one release delivered in fixed dependency order M0 then M1 then M2; scope breadth may shrink under resource pressure, but tenant isolation, authorization, fail-closed behavior, idempotency, audit completeness, and safe AI approval cannot be cut.
- (decision) M0 proves the complete UI-only vertical for one tenant and one controlled mailbox pattern, with human-driven association and approval, governed attachments, one allowlisted AI action, and required safety and audit behavior.
- (decision) M1 adds CLI and MCP parity, service-client permissions, outbound draft-and-send, and full tenant governance through one shared command pipeline so surface parity is structural rather than a separate implementation.
- (decision) M2 is the production-operability increment, adding dashboards, recovery and replay isolation, per-operation idempotency, tamper-evident audit storage, measurable audit completeness, and storage-level isolation for derived AI data.
- (decision) The interactive chat surface is an MVP governed write surface delivered through Epic 10 and the FrontComposer shell; every message enters through the command gateway and risky requests become approval-gated proposals, with no ungoverned freeform path.
- (decision) Rejected and Failed association workflows are terminal and reprocessing creates a new audit-linked workflow instance; corrections preserve prior history, invalidate all affected derived context, and block AI use until propagation completes.
- (decision) All state-mutating paths require audit readiness and idempotency: audit unavailability fails closed without durable mutation, and duplicate or retried delivery must converge on the same observable state without duplicate artifacts.
- (decision) The MVP excludes autonomous project creation, general email-client replacement, full task lifecycle, broad document intelligence, unrestricted commands, cross-tenant suggestions, extra messaging channels, broad trigger automation, and commercial packaging so the governed email loop stays buildable.
- (decision) WCAG 2.2 AA is a release gate for the UI surfaces introduced in each increment, while CLI and MCP are outside WCAG scope because they are machine and command surfaces.
- (change) Jerome authorized the recommended 2026-09-13 review remediation set; the PRD was reopened as draft for contract reconciliation and re-validation.
- (decision) Low-risk AI assistance is limited to versioned read-only no-external-effect subtypes; state mutation, file exposure, external sends, task creation, tool invocation, and acting on behalf remain structurally non-downgradable approval-required effects.
- (decision) AI Command Allowlist v1 is deny-by-default and contains exactly Project.AppendConversationMessage and ChatBot.ExecuteLowRiskAssistance; administrative, identity, policy, permission, allowlist, and outbound mutations are never AI-invocable in MVP.
- (decision) Canonical audit durability is atomic with domain mutation and idempotency state; post-commit audit views are rebuildable projections and cannot be the mutation safety boundary.
- (override) Derived-store tenant isolation proof moves from a broad M2-only gate to the first increment that introduces each store; M2 retains isolation obligations only for M2 stores and recurring production probes.
- (decision) Governed interactive chat is assigned to M1 as an MVP FrontComposer write surface through the shared command pipeline and its WCAG gate.
- (decision) The minimum inbound authenticity floor ships in M0; M1 adds advanced tenant tuning and broader provider compatibility.
- (override) Skipped is a valid M0 terminal lifecycle state because duplicate suppression and out-of-scope intake require it, superseding the legacy M1-only note.
- (decision) Durable mutations use stable operation IDs and human decisions use one authoritative decision-slot ID; time-window hashes are evidence, not durable identity.
- (decision) Association scoring, task-intent detection, and action-risk classification are separate versioned contracts; fail-closed association outcomes enter NeedsReview with typed reasons.
- (decision) Subject is plain-language framing only; actionable collaboration must resolve to a governed Project boundary and general non-project workspaces are post-MVP.
- (decision) Hexalith.Conversations owns conversation identity and messages; Projects references conversation IDs within project membership and boundaries.
- (decision) Current-run story-completion recovery evidence and retained operational recovery evidence serve separate trust purposes and cannot substitute for each other; A10 remains provisional pending fresh qualifying hosted evidence.
- (decision) General user-upload ingestion is deferred post-MVP so the MVP proves governed mailbox attachment capture first.
- (decision) M0 is a controlled pilot preview, M1 is the governed cross-surface pilot, and M2 is the MVP production release-candidate gate; pilot deployment is not production approval.
- (decision) A6 data-protection reconciliation is a pre-pilot blocker owned by Compliance Data Protection and Architecture; GDPR satisfaction is not claimed until the data-class contract is approved.
- (decision) IdentityEvolved is an unaccepted external dependency rather than a binding event contract until producer teams approve its versioned schema, authority, ordering, replay, compatibility, reconciliation, and fallback rules.
