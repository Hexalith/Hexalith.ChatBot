Epic 9 is the **final epic in the roadmap** — there is no Epic 10. It is the M2 compliance-and-recovery capstone: it makes audit *defensible* (tamper-evident WORM hash chain with GDPR-safe erasure), makes "complete audit" *provable* (reconstructability as a measured production observable rather than field-presence), gives compliance a *safe* investigation surface (S9, read/escalate-only), isolates *replay/simulation* from production, isolates *derived stores* (vector/embedding/cache) cross-tenant at the storage layer, *reindexes* derived material after correction, and lands the *retention / export / deletion / consent* data-governance workflows plus the *continuity / RPO-RTO / projection-rebuild / scoped-outage* recovery validation drills.

Epic 9 delivered all of this with the same architectural spine that carried Epics 7 and 8: define-once contracts, metadata-only safe-token payloads, fail-closed authorization, and — for the third epic running — **correct, tested logic whose runtime activation is deliberately deferred**.

- **WORM hash-chained audit (9.1)** — per-tenant append-only chain (each envelope carries its predecessor's hash, genesis = 64-zero sentinel), deterministic canonical serialization (fixed field order, invariant culture, UTC), GDPR erasure by appended redaction record + key-shred + projection tombstone (never chain mutation), and a fail-open-then-reconcile post-commit design so chain append never blocks the command commit. ADRs `audit-two-phase.md` and `worm-audit-backing.md`.
- **Audit completeness as reconstructability (9.2)** — `AuditOperationReconstructor` proves an operation rebuilds end-to-end from the chain alone (presence is only a precondition), measured over a rolling 7-day per-tenant window with a <99.5% → P1 budget evaluator; replay envelopes excluded from numerator and denominator via a version-bumped canonical hash (`v1`→`v2`) carrying `ReplayRunId`.
- **S9 compliance investigation surface (9.3)** — query by tenant/actor/command/resource/decision/reason/correlation/message-id/surface/time over the WORM chain (wiring Story 7.4's forward-scaffolded contracts + read policy), per-project redaction driven by *actual* `project-owner` grants, read/escalate-only authority (no mutation), replay-marked records excluded from default queries. **This story added the epic's only new public HTTP shapes.**
- **Replay/simulation isolation (9.4)** — `ReplayRunId` threaded structurally from `ChatBotCommandSubmission` → immutable `ChatBotGatewayContext` → the single `AuditEnvelopeFactory.Create` point (un-rewritable downstream), a test-tenant-only intercepting outbound adapter that records the would-have-sent metadata instead of sending, and a nightly isolation probe (M2 release gate) asserting no replay run ever wrote to a production tenant's outbound-trace store *or* WORM chain.
- **Derived-store cross-tenant isolation (9.5)** — a single-source `DerivedStorePartition` contract physically partitioning vector/embedding/prompt-context/candidate-ranking stores per tenant (tenant-first nested storage makes a cross-tenant read a structural key miss, not an application filter), with an active-negative nightly probe (seed under owner, attempt read through intruder scope; a *successful* read = stop-ship breach).
- **Correction-driven vector reindexing (9.6)** — `ReindexVectors(tenant, correctionId, sourceVersion)` with a version-guard ledger whose watermark advances only *after* invalidate+rebuild completes (split `ShouldReindex`/`TryAdvance`), structural invalidation via `IDerivedStore.InvalidateAsync` (not a filter flag), consuming the single `CorrectionPropagationSlo` (M2 60-min) with P2 `correction-delayed` on overrun.
- **Data-class inventory + retention policy (9.7)**, **tenant export (9.8)**, **deletion/erasure (9.9)**, **consent/lawful-basis (9.10)** — a four-story data-governance block built as structural twins of Story 7.4's retention-change machinery: a single canonical `ComplianceRetentionClassIds` set (13 members), pure planners consuming bounded authority views (never `ClaimsPrincipal`), schema-level completeness/quarterly invariants, `audit-records` deletion behavior constrained to `retain-immutable`/`projection-tombstone` (never `hard-delete`), absolute-over-authority WORM behavior (ambiguous cases bias to `retained`), `sha256:` manifest/proof fingerprints over succeeded classes only, and fail-closed-and-audited gateway gating on every command. Erasure orchestrates Story 9.1's real `AuditRedactionService` and the chain still verifies after.
- **Recovery validation harnesses (9.11 continuity drill, 9.12 projection rebuild, 9.13 scoped outage)** — pure evaluators + fail-closed coordinators (mirroring the 9.4/9.5 probe shape, *not* the governed-command shape), single-source `RecoveryTargets` (RPO ≤ 15 min, RTO ≤ 4 hr, scope-recording ≤ 5 min) shared across all three, and a deliberate verdict trichotomy — `met`/`missed`/`unmeasurable` (9.11), `equivalent`/`divergent`/`duration-exceeded`/`unmeasurable` (9.12), `contained`/`breached`/`late-recording`/`unmeasurable` (9.13) — where an unmeasurable run is a breach signal, never a fabricated pass.

## What Went Well

- **Compositional story design — each story built on the last by reference, not by copy.** 9.1's `IWormAuditStore`/`AuditEnvelopeFactory`/`AuditRedactionService` are consumed directly by 9.2 (reconstruct), 9.3 (query), 9.4 (replay marker), and 9.9 (erasure). 9.5's `DerivedStorePartition`/`IDerivedStore` are consumed by 9.6 (reindex/invalidate). 9.7's `ComplianceRetentionClassIds` + `DeletionBehavior` drive 9.8 (export eligibility), 9.9 (deletion action), and 9.10 (consent class). 9.11's `RecoveryTargets` is reused verbatim by 9.12 and 9.13. No second redaction set, no second class-id set, no second recovery constant — define-once held across thirteen stories.
- **Marker-plumbing built deliberately across stories, then populated for real.** `ReplayRunId` was introduced as a field + hash coverage + query predicate in 9.2/9.3 against *synthetic* records, then 9.4 threaded it structurally from the command boundary so the exclusions fire against *real* marked envelopes. Building infrastructure, exercising it synthetically, then populating it in a later story proved a reliable pattern.
- **Tenant isolation by construction, not by filter.** 9.5's physical per-tenant partitioning makes a cross-tenant derived-store read a structural key miss below the application layer (NFR9a) — the security model is the storage shape, not a `WHERE tenant = ...` clause an app bug could drop. The active-negative probe (a *successful* cross-tenant read is the breach) is the right inversion.
- **Zero CRITICAL / zero HIGH across the whole epic.** Every review finding was MEDIUM-or-lower and most were bookkeeping. The substantive catches were genuine and small: 9.6's version-guard watermark advancing before reindex completed (split into `ShouldReindex`/`TryAdvance`), 9.2's `ChatBotAuditPathMap` comment claiming a never-reachable `StateTransition` fallback, 9.1's benign field-separator reuse in the canonical hash.
- **WORM-vs-erasure paradox resolved cleanly and proven.** Erasure never mutates the chain: it appends a redaction record, shreds the key, and tombstones the projection (architecture cross-cutting #13). 9.9 orchestrates 9.1's real `AuditRedactionService` rather than reimplementing crypto-shred, and a test asserts the chain still verifies end-to-end after erasure — the single hardest compliance constraint in the epic, met and tested.
- **Fail-safe / no-fabrication doctrine carried from Epic 8 and deepened into a verdict trichotomy.** The validation harnesses don't collapse failure into a boolean. `unmeasurable` (no evidence) is held distinct from `missed`/`duration-exceeded`/`late-recording` (a real but non-stop-ship recalibration signal) and from `divergent`/`breached` (stop-ship-class isolation/determinism failure). A release gate can assert `Unmeasurable == 0` (evidence was produced) separately from `Breached == 0` (no isolation breach) — different failure modes get different gates.
- **Inert deferrals are honest and have teeth.** `DeferredContinuityDrillScenarioRunner` (and its 9.12/9.13 siblings) throw `NotSupportedException`, which the coordinator's fail-safe catch turns into an `unmeasurable` report — the deferral cannot masquerade as a passing drill. Every story's Completion Notes state the deferral explicitly.
- **Per-story ADRs are the best provenance trail in the project.** Fourteen ADRs under `docs/adrs/` (one per story plus the two-phase/backing pair), each recording the decision, the NFR/architecture bind, the M2 live-target convention, and the explicit deferrals — and cross-referencing the prior stories' ADRs to establish lineage.
- **Metadata-only / safe-token floor upheld on every new surface (Epic 8 AI#4 delivered).** The WORM chain, the S9 query results/detail/timeline/escalation payloads, export manifests, erasure proofs, derived-store entries, and every probe/drill report carry only safe tokens and `sha256:` digests; no-leak serialization suites assert the banned sentinels never appear. The `IsSafeToken`/marker-ban posture extended cleanly to audit-query results and export payloads exactly as the Epic 8 action item asked.

## Key Insights

1. **Compositional design beat copy-paste.** Epic 9's thirteen stories form a dependency lattice (chain → measure → query → mark → partition → reindex → govern → validate) in which each story consumes its predecessors' contracts by reference. This is the maturation of the "define-once, reuse" economy first seen with the governed-operation aggregate — and it is why a 13-story epic produced zero HIGH findings.
2. **Build infrastructure, exercise it synthetically, populate it for real later** is a deliberate and repeatable multi-story pattern (the `ReplayRunId` arc across 9.2 → 9.3 → 9.4). It lets the hardest-to-test exclusion logic ship with synthetic coverage and gain real coverage only when the producing path exists.
3. **Isolation by construction is a different (and stronger) claim than isolation by filter.** Physical per-tenant partitioning (9.5) makes the failure mode a key miss below the app layer; the active-negative probe (a successful cross-tenant read = breach) tests the claim the right way around. This should be the template for any future derived/cached store.
4. **A verdict trichotomy is a safety feature.** Separating `unmeasurable` (breach — no evidence) from `missed`/`duration-exceeded`/`late-recording` (recalibration signal) from `divergent`/`breached` (stop-ship) lets each failure mode drive the gate it deserves, and prevents a "no data" run from ever reading as a pass. Fail-safe over fabrication, formalized.
5. **The recurring failure mode is unchanged across three epics and is now diagnostic: a detection-only control left to manual discipline will keep failing.** Bookkeeping drift was an Epic 7 finding, an Epic 8 finding *with a named prevention action item*, and an Epic 9 finding in nearly every story. The action item to convert detection → prevention was itself not done. The lesson is meta: action items that require building a mechanical gate do not get done as side work — they must be a story.
6. **Deferred-runtime debt has now compounded across three epics and the predicted forcing function did not force it.** The Epic 8 retro correctly predicted 9.2 would require a live loop; 9.2 deferred it anyway. There is no longer a future story that will "naturally" force the wiring — every story that needed it has shipped without it. The runtime loop will exist only when it is made a first-class deliverable.
7. **"Provable" and "proven" are different M2 claims, and Epic 9 delivered the former.** Audit completeness, replay isolation, derived-store isolation, RPO/RTO, deterministic rebuild, and scoped degradation are all now *measurable by construction* with tested verdict logic. None has yet been *measured against a deployed environment*, because the probes/drills have no runtime trigger and the live drivers are deferred. Closing the M2 claims means wiring the runtime and recalibrating the A10 [ASSUMPTION] targets against real drills.
