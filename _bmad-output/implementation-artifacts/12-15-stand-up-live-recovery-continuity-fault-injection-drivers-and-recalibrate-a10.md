### Binding implementation obligations

The following obligations make the canonical criteria testable against the repository as it exists at baseline commit `1493ff8f`:

- **Real means primary-path evidence, not a scripted measurement.** A live run must cause an observable fault at an Aspire resource or composed dependency boundary, exercise the real coordinator/evaluator/audit path, inspect post-recovery state, and retain enough provenance to reproduce the result. A test double that simply returns a preselected `*Measurement` cannot satisfy AC1 or AC2.
- **Fault authority stays outside the ChatBot process.** The Tier-3/AppHost orchestration boundary owns stopping, starting, restarting, or faulting composed resources. The Server must not request or acquire general-purpose AppHost/DCP control, expose an unauthenticated fault endpoint, or be able to target an arbitrary resource or tenant. Any bounded provider simulator/control seam is owned and invoked by the opted-in Tier-3 harness.
- **Activation is doubly opt-in and fail closed.** Live drivers and their scheduler/release-gate path are disabled by default. The Tier-3 harness may compose/run them only when an explicit live-recovery-validation option is enabled *and* the configured tenant satisfies `ReplayTenantPolicy.IsTestTenant` (`replay-test:` prefix). Missing controller capability, wrong environment, wrong tenant, empty dataset, zero scenario coverage, timeout, cleanup failure, or missing evidence yields `Unmeasurable`/stop-ship; it never falls back to the deferred or scripted implementation and never becomes a pass.
- **The two A10 drills are mandatory.** The EventStore outage and M365 subscription-failure scenarios must both execute end to end in the Aspire/DAPR sandbox. The current topology has no live Microsoft Graph/M365 resource, so the M365 exercise must fault the real ChatBot subscription-processing boundary through a controlled, topology-composed Graph/subscription simulator and record external-M365 equivalence as a residual. It must not claim production Graph fidelity.
- **The rebuild and all six scoped-outage dependencies are mandatory.** Rebuild uses a versioned baseline dataset and only immutable `ProjectConversationSourceEmailView` records plus `IWormAuditStore` history—never Graph, mailbox re-ingestion, current upstream Party/Folder state, or sibling-tenant context. Scoped-outage validation covers the canonical `graph`, `identity`, `ai-provider`, `command-execution`, `audit-store`, and `attachment-processing` tokens; `graph` also covers expired-subscription behavior and is not duplicated as a seventh token.
- **Existing verdict semantics are preserved.** Continuity keeps `met | missed | unmeasurable`; projection rebuild keeps equivalent/divergent, duration-exceeded, and unmeasurable as separate dimensions; scoped outage keeps contained/breached, late scope recording, and unmeasurable separate. An honest measurable target miss is evidence for remediation or recalibration. An unmeasurable result is always a breach signal. No evaluator threshold or fail-safe behavior may be weakened to make the run pass.
- **A10 is only RPO/RTO.** RPO ≤ 15 minutes and RTO ≤ 4 hours are the A10/NFR56 starter targets. Projection rebuild ≤ 4 hours is NFR57, and scope/dependency recording ≤ 5 minutes is NFR41. Measure all three families, but do not describe the rebuild or scope-recording targets as A10 values.
- **Story 12.14's handoff is completed safely.** The required Tier-3/release workflow—not the ChatBot process—schedules and orchestrates the destructive live validation. Release concurrency is **per-commit and non-cancelling** (`github.sha` concurrency group): that preserves a required check for every publishable commit and accepts N concurrent 5.5-hour jobs inside the window instead of a shared queue that GitHub can cancel. CI remains schedule/`workflow_dispatch` only. Its fail-closed evidence gate must cover all three coordinators. Do not add the live faults to the general `PeriodicEnforcementBackgroundService`: a Server-hosted driver cannot safely or technically stop its own Aspire/DCP resource. If the ADR also publishes live-validation status through the existing M2 readiness model, it may ingest externally produced evidence but must not acquire resource-lifecycle authority. General deployments retain inert, fail-safe defaults. The release path fails closed on disabled required validation, never-run/incomplete/stale/future evidence, exception/timeout/cleanup failure, unmeasurable or serious breach, zero coverage, or missing scenario/dataset provenance.
- **Evidence is retained and reviewable.** CI uploads the raw `.trx` test output and the retained reports/manifests as a workflow artifact even on failure — narrowed from `.trx`/logs/traces/metrics by the round-5 decision, because requiring locators for artifacts the lane never produced only guaranteed every manifest carried syntactically valid links to nothing; the gap is carried as residual `RV-EVIDENCE-KINDS`, while the story Completion Notes retain the CI run locator, artifact name, topology commit/configuration, dataset identity/volume, report summary, and residual IDs. Do not describe ignored local `TestResults` files as repository-retained evidence.
- **Recalibration is governed, not automatic.** Runtime code never mutates `RecoveryTargets`. Winston reviews the evidence and Murat validates authenticity. If A10 is confirmed, remove/resolve the A10 assumption in the canonical PRD decision record and state the committed values. If a target changes, update the PRD decision record, the owning ADR, and `RecoveryTargets` in the same reviewed change, state whether the numeric threshold became stricter or looser, and link the evidence and rationale. A miss may instead produce corrective work and a rerun; it does not automatically justify loosening the commitment.

### Required live scenario and evidence matrix

| Exercise | Required live scenario | Minimum proof |
| --- | --- | --- |
| Continuity | `eventstore-outage` | The orchestrator stops or otherwise makes the real sandbox EventStore resource unavailable, the application observes the fault, restoration occurs, and measured RPO/RTO, reconstructable committed operations, data-loss, tenant-isolation, and unauthorized-mutation checks are reported. |
| Continuity | `m365-subscription-failure` | A topology-composed subscription boundary expires/fails, the real subscription recovery path is exercised, and measured RPO/RTO plus no-loss/no-duplicate/no-cross-tenant assertions are reported; external Graph equivalence is explicitly residual. |
| Projection rebuild | Configured versioned baseline dataset | A fresh isolated test partition is rebuilt from immutable source metadata plus WORM history only; schema/version and structural digests are diffed; duration, resource count, tenant isolation, and absence of mailbox re-ingestion are proven. |
| Scoped outage | `graph` | Only the expected mailbox/subscription scope degrades; unrelated tenant/mailbox work remains available; recovery produces no duplicate side effects. |
| Scoped outage | `identity` | Authentication/authorization fails closed at the expected service-client/command scope; no broad fallback access or unauthorized mutation occurs. |
| Scoped outage | `ai-provider` | The AI-dependent operation degrades at the expected scope while dependency-independent paths remain usable where their dependency graph permits. |
| Scoped outage | `command-execution` | The affected operation reaches a visible recoverable state and resumes without duplicate effects after restoration. |
| Scoped outage | `audit-store` | Governed mutation fails closed when required audit evidence is unavailable; no silent data loss or unauthorized commit occurs. |
| Scoped outage | `attachment-processing` | Partial attachment failure remains bounded to the workflow item/attachment scope, is visible and recoverable, and exposes no unauthorized content. |

### Architecture guardrails

- Preserve the dependency direction and domain purity described in `architecture.md`: Contracts remain technology-neutral; the Domain does not acquire Aspire/DAPR/fault-injection dependencies; infrastructure composition belongs in Server/AppHost/test infrastructure.
- One C# type per file, current namespace/layout conventions, XML documentation on internal/public types, nullable/warnings-as-errors, and central package management remain mandatory. Do not add inline package versions or upgrade Aspire/DAPR for this story.
- Use ULIDs for durable run/scenario identifiers. Use UTC timestamps and `TimeProvider`/the repository clock abstraction; do not use ad hoc local time.
- DAPR resiliency retries, timeouts, and circuit breakers may mask an outage. Record the effective policy and prove the injected fault reached the intended boundary before starting the recovery measurement. Do not assume HTTP and gRPC invocation paths have identical resilience behavior.
- Every destructive action must be allowlisted, target-resolved before execution, and restored in `finally`. After restoration, wait for declared health and run an end-state assertion. A failed cleanup is part of the verdict and release status, not a log-only warning.

- A sandbox pass proves only the exact topology, configuration, scale, replicas, dataset, and external simulators named in its manifest. It does not prove AKS, production Graph, multi-replica scheduler/lease behavior, or durable production bindings unless those were actually present.

### Measurement and evidence rules

- Derive wall-clock start/end and durations from observed state transitions. Store both the target and measured value. A hardcoded duration, seeded verdict, or report assembled without a witnessed fault is fabricated evidence.
- RPO is proven by comparing the known committed-before-outage set with what is reconstructable after recovery; RTO ends only when the defined service/data recovery condition is healthy and end-state checks pass.
- Rebuild evidence includes dataset version/volume, immutable-source and audit-chain counts, projection schema versions, structural digests, resources compared, first divergence, and measured duration. Preserve failed rebuild partitions until evidence capture completes, then clean them safely.
- Scoped-outage evidence includes dependency, expected/observed scope, application-observed degradation/recovery, unaffected control operation, the three NFR59 safety assertions, in-flight recovery, duplicate-effect check, and measured scope-recording latency.
- Reports remain the canonical domain evidence objects. The live evidence manifest adds execution provenance and raw-artifact locators; it must not invent a second verdict model.
- A CI artifact upload is retention for the configured workflow period, not repository history. Completion Notes must say which retention mechanism applies and must not call a local ignored `.trx` “retained.”

### A10 decision semantics

`RecoveryTargets.MaxRpo = 15 minutes` and `MaxRto = 4 hours` are currently the single runtime source for A10/NFR56. The PRD describes them as starter targets pending this M2 drill. After the required EventStore and subscription exercises:

- **Confirm:** keep the numeric values, update the A10 decision/assumption marker to an evidence-backed commitment, and link the run.
- **Tighten:** a smaller maximum RPO/RTO is a stricter commitment; update the PRD, ADR, and `RecoveryTargets` together after review.
- **Loosen:** a larger maximum is a weaker commitment. It requires explicit rationale, release/product approval, risk/follow-up ownership, and the same atomic documentation/code update; a test timeout or unmeasurable run is not evidence for loosening.
- **Remediate and rerun:** keep the starter target, record the miss, implement corrective work, and repeat the drill. This is preferable when the target remains required.
- **Remain provisional** *(added by the round-4 review, 2026-08-01)*: keep the numeric values and record explicitly that the drill did **not** discharge the assumption. This is the correct outcome when the run passes but produces no retained hosted artifact locator, or when the lane's measurable ceiling sits below the target being claimed — a pass that cannot fail is not a confirmation. **Exit condition:** a complete passing scheduled-CI or release artifact whose hosted run/artifact locator is recorded in `.decision-log.md`, and whose claim limitations do not cover the target being ratified. **Owner:** Architecture/DevOps. This branch exists because the first four assume the drill can both pass and fail against the target; a sandbox lane that can only pass satisfies none of them, and forcing the outcome into "Confirm" would launder an unfalsifiable run into a commitment.

**Un-ratification.** A ratified A10 returns to provisional when the cited artifact ages past the 30-day retention boundary without a successor, when a later required run is not passing, or when a hosted run returns `Unmeasurable` or a structural breach. Architecture/DevOps owns the transition and records it in the decision log. Note also that the gate's `MaximumEvidenceAge` is 8 days: an artifact aged 8–30 days is still downloadable but is no longer citable for ratification.

The projection-rebuild and scope-recording decisions are recorded against NFR57 and NFR41 respectively, even when the same evidence bundle is reviewed.
