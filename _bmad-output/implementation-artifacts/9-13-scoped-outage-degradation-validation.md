# Story 9.13: Scoped outage degradation validation

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an operations owner,
I want dependency outages to degrade only the affected scope,
so that failures do not leak across tenants, mutate unauthorized state, or lose data silently.

## Acceptance Criteria

1. **A dependency outage degrades only the affected scope; resilience validation proves no cross-tenant leakage, unauthorized state mutation, or silent data loss (NFR58, NFR59).**
   **Given** a dependency outage of one of the six NFR59 dependencies — `graph` (degraded Graph access **and** expired M365 subscription, the mailbox boundary), `identity` (Keycloak), `ai-provider`, `command-execution`, `audit-store`, or `attachment-processing`,
   **When** the outage occurs against the validation test tenant,
   **Then** the `ScopedOutageDegradationValidationCoordinator` drives the outage through the `IScopedOutageInjectionDriver` seam, the pure `ScopedOutageDegradationEvaluator` folds the measured assertions into a verdict, and a `contained` verdict requires that the **observed degradation scope is within the expected narrowest scope** (no unrelated tenant/mailbox/operation/service-client/command-surface/workflow-item blocked — NFR58) **and** the three NFR59 isolation assertions all hold: **no cross-tenant leakage, no unauthorized state mutation, no silent data loss**.
   - **Scope is a closed vocabulary, dependency is a closed vocabulary.** The affected scope is one of the `ScopedOutageScopes` tokens (`tenant` / `mailbox` / `operation` / `service-client` / `command-surface` / `workflow-item`, the NFR41/NFR58 narrowest-scope axes) and the dependency is one of the `ScopedOutageDependencies` tokens. An unknown dependency or scope token biases to `unmeasurable` (fail-safe), never a fabricated `contained` — exactly the `ContinuityDrillScenarios.Contains` discipline.
   - **`graph` covers both degraded Graph access and expired-subscription lapse.** Per architecture (M365/Graph = mailbox boundary, degraded per-mailbox, never tenant-wide), the `graph` dependency-outage scenario validates NFR59's "degraded Graph access" **and** "expired subscriptions" — both degrade at the mailbox boundary; `ai-provider`/`command-execution`/`audit-store`/`attachment-processing` map 1:1 to NFR59, and `identity` (Keycloak) is the AC1 sixth dependency. Do **not** add a seventh `subscription-expiry` token.
   - **Test-tenant by construction (no production mutation).** Like the 9.4 replay probe, the 9.11 drill, and the 9.12 rebuild, the validation runs against a **test tenant** resolved by the single authoritative `ReplayTenantPolicy.IsTestTenant` predicate; it mutates **no** production-tenant durable state. A production-tenant target fails closed to `unmeasurable` and the driver is **never** invoked. Do **not** add a second test-tenant discriminator or a "inject outage on a production tenant" flag.
   - **Fail-safe over fabrication (Epic 8/9 no-fabrication doctrine).** A validation that **cannot complete** — the driver throws, the outage exercise never finishes, or the assertion results are unavailable — yields `unmeasurable` (a breach signal), **never** a fabricated `contained`. Mirror `ContinuityDrillReport.Unmeasurable(...)`, `ProjectionRebuildReport.Unmeasurable(...)`, and `ReplayIsolationStatus.Unknown` exactly.

2. **Each outage scenario asserts no cross-tenant leakage, no unauthorized state mutation, and no silent data loss, each assertion producing an evidence artifact (NFR59).**
   **Given** each of the six dependency-outage scenarios,
   **When** validated,
   **Then** the resilience validation independently asserts the **three NFR59 properties** and the pure `ScopedOutageDegradationEvaluator.Deviations(...)` records exactly the bounded deviation tokens for the assertions that failed: `cross_tenant_leakage`, `unauthorized_mutation`, `silent_data_loss` (plus `scope_escape` for an NFR58 scope breach), in a stable order. The metadata-only `ScopedOutageDegradationReport` **is** the per-scenario evidence artifact (dependency + expected/observed scope + the three assertion outcomes + verdict), and the structured `ScopedOutageDegradationOutcome` is the aggregate sweep evidence a release gate asserts.
   - **These three assertions are stop-ship-style isolation breaches (the serious dimension), analogous to the 9.4/9.5 isolation probes.** A `breached` verdict (any of cross-tenant leakage / unauthorized mutation / silent data loss / scope escape / non-recoverable in-flight / duplicate side effect) is the serious NFR58/NFR59 breach — a determinism/isolation-class defect a release gate treats as stop-ship (`Breached == 0`). Keep `breached` distinct from a `contained`-with-late-recording (see AC4) in the outcome.
   - **Reuse the cross-tenant leakage harness — do NOT build a new no-leak path.** Extend the `CrossTenantLeakageScanner` / `CrossTenantLeakageCorpus` conformance suite (Story 1.12) to assert no foreign-tenant sentinel survives serialization of `ScopedOutageDegradationReport`, `ScopedOutageDegradationOutcome`, and the `ScopedOutageDegradationBreach` audit envelope. **Use a neutral, non-sentinel tenant token** (e.g. `tenant-scoped-outage`) — `tenant-alpha` is the Story 1.12 corpus `BoundTenant` sentinel and `tenant-beta` the `ForeignTenant` (the 9.8–9.12 leakage-scan gotcha).

3. **On recovery, in-flight items resume from a visible recoverable state (pending/retryable) with no duplicate side effects (NFR17, NFR13).**
   **Given** the dependency recovers,
   **When** the outage is restored,
   **Then** the measurement asserts in-flight workflow items resume from a **visible recoverable state** (`pending`/`retryable` — NFR17, never a silent drop or a hidden terminal state) and that recovery produces **no duplicate side effects** (NFR13 idempotency — a re-dispatched command/outbound action is suppressed by the existing idempotency seam, not re-executed). The evaluator records `inflight_not_recoverable` (NFR17) and `duplicate_side_effect` (NFR13) deviations and folds either into a `breached` verdict.
   - **Do NOT re-implement idempotency or recoverable-state machinery — assert against it.** NFR13 idempotency (coarse request-dedup + fine event-dedup) and NFR17 visible-recoverable-state lifecycle already exist (`CoarseIdempotencyOperationClass`, the `pending/retryable/failed/quarantined/needs-review` state enums). This story's measurement reports **whether** recovery honored them; it adds no new idempotency cache and no new state machine.

4. **A scoped degradation records incident scope + dependency within 5 minutes where monitoring is available (NFR41).**
   **Given** a scoped degradation with monitoring available,
   **When** detected,
   **Then** the measurement carries the detection→scope-recording latency and the coordinator computes `ScopeRecordedWithinTarget = measurement.ScopeRecordingLatency <= RecoveryTargets.MaxScopeRecordingLatency` (the single-source **5-minute** NFR41 budget). A `ScopeRecordedWithinTarget == false` is a **monitoring-latency miss** — a recorded deviation (`scope_recording_exceeded`) that is a recalibration/follow-up signal **analogous to the Story 9.12 duration overrun**, **not** by itself an isolation breach: the verdict stays `contained` while still failing-closed-audit-then-alert so the slow recording is surfaced.
   **And** on a **breach** — a `breached` verdict (an isolation/scope/recovery breach), an `unmeasurable` validation (fail-safe), **or** `ScopeRecordedWithinTarget == false` (a monitoring-latency miss) — the coordinator does **fail-closed audit-then-deliver**: it writes the `AuditEnvelopeFactory.ScopedOutageDegradationBreach` pre-commit envelope **before** emitting exactly one `OperatorAlertKind.ScopedOutageDegradationBreach` alert through the existing `IOperatorAlertSink`.
   - **Three distinct breach dimensions — keep them distinct in the outcome.** `breached` (cross-tenant leakage / unauthorized mutation / silent data loss / scope escape / non-recoverable in-flight / duplicate side effect) is the **serious** NFR58/NFR59 breach (stop-ship-style, like a 9.4/9.5 isolation breach — a gate asserts `Breached == 0 && Unmeasurable == 0`). A **late scope recording** (`ScopeRecordedWithinTarget == false`) is a monitoring-latency **miss** (recalibration signal — like the 9.11 RPO/RTO miss / the 9.12 duration overrun): a contained-but-slow degradation stays `contained` with `ScopeRecordedWithinTarget == false`. `unmeasurable` is the **fail-safe** breach (no evidence produced). The `ScopedOutageDegradationOutcome` keeps `Contained` / `Breached` / `ScopeRecordingExceeded` / `Unmeasurable` distinct so a gate asserts the dimension it cares about. Never collapse `breached` or `unmeasurable` into `contained`, and never let a late scope recording silently pass.

### Cross-cutting requirements that hold for every AC

- **This is the resilience-validation harness story — the third Epic 9 recovery/continuity validation (9.11 drill → 9.12 projection-rebuild → 9.13 scoped-outage degradation). It is NOT a governed-command story and NOT the runtime degradation surface (Story 8.5 owns that).** It is the direct sibling of the Story 9.2 completeness measurer, the 9.4/9.5 isolation probes, and the 9.11 continuity drill / 9.12 rebuild validation — a **pure evaluator + an injectable coordinator + a structured outcome + fail-closed audit-then-deliver + a metadata-only report**, all server-internal in `.Server/Audit/`. There is **no** `IChatBotCommand`, **no** `ChatBotSpineCommandAllowlist` entry, **no** `ParticipantAuthorizationStage` gating block, and **no** `.Contracts` change. Story 8.5 already owns the **runtime** scoped-degradation behaviour (the `DependencyDegraded` `OperatorAlertKind`, the degraded-state surface rendering, the 5-min incident-status recording); 9.13 is the **validation that proves** that behaviour holds under each NFR59 outage — do not re-implement the runtime degradation, the `DependencyDegraded` alert, or the surface. Copying the 9.7–9.10 governed-command shape here is the primary anti-pattern to avoid.
- **Inert-control-floor honesty (the defining constraint — say it explicitly in Completion Notes).** What ships and is fully built+tested: the `ScopedOutageDependencies` + `ScopedOutageScopes` + `ScopedOutageDegradationVerdicts` token sets, the `ScopedOutageDegradationMeasurement` record, the pure `ScopedOutageDegradationEvaluator`, the `ScopedOutageDegradationReport` artifact + `Unmeasurable` factory, the `ScopedOutageDegradationValidationCoordinator` (run-scenario + sweep, fail-closed audit-then-alert, deviation recording, test-tenant-by-construction, no-production-mutation assertion), the `ScopedOutageDegradationOutcome` gate contract, the new `OperatorAlertKind.ScopedOutageDegradationBreach`, the `AuditEnvelopeFactory.ScopedOutageDegradationBreach` envelope, and the `RecoveryTargets.MaxScopeRecordingLatency` NFR41 constant. **Deferred** (documented seams, exactly like Story 9.4's deferred replay driver, 9.11's deferred fault-injection runtime, 9.12's deferred rebuild driver): (a) the **live fault-injection runtime** that actually downs a real Graph/identity/AI/command/audit/attachment dependency against a deployed AKS/Aspire environment and measures the real degradation scope + assertions — modeled behind an `IScopedOutageInjectionDriver` seam the coordinator consumes (tests drive it with a deterministic scripted fake returning the measured assertions); (b) the periodic scheduler / release-gate wiring (no always-on `BackgroundService`). The evaluator, coordinator, report, alert path, and gate outcome are real and tested; only the live fault-injection runtime and the periodic trigger are deferred. **Never let a deferral read as "scoped degradation is unproven/unmeasured"** — the containment semantics, the three NFR59 assertions, the recovery-resume checks, the 5-min scope-recording check, and the fail-closed evidence path are all real and tested against the driver seam.
- **Fail-safe / no-fabrication floor (Epic 8/9 spine doctrine).** Prefer `unmeasurable` over a fabricated `contained`. A validation whose driver throws, whose outage exercise never completes, or whose assertion results are unavailable is `unmeasurable` (a breach signal that fail-closed-audits-then-alerts), never a silent pass. Mirror `AuditCompletenessMeasurer`, `ContinuityDrillCoordinator` (catch ⇒ unmeasurable), and `ProjectionRebuildValidationCoordinator`.
- **Metadata-only / no-leak floor (NFR2, NFR42, NFR45).** Every report field, outcome field, measurement field, deviation token, alert payload, locator, scope token, dependency token, and verdict token is an `AuditMetadata`-safe bounded token (ASCII alnum + `.-_:@|`, marker-ban on `secret`/`password`/`bearer`/`token`/`exception`/file-extension sentinels). The report records **no** raw email content, recipient addresses, subject, body, prompts, payloads, foreign-tenant identity, or vector/embedding values — only safe tokens, the integer-second latency, counts, booleans, and bounded reason codes. Reuse `AuditMetadata.SafeOptionalToken` / `IsSafeStableIdentifier` for any locator. Metric/alert dimensions stay low-cardinality (`tenant` + bounded `dependency`/`verdict`/`reason` only — never ids/correlation in a metric tag).
- **Read-mostly / out-of-band — the commit path is untouched (D4, two-phase audit, NFR15a).** The validation injects an outage out-of-band against the test tenant and reads the resulting state; it adds **no** commit-time gate and never mutates the audit chain. Its only writes are (i) into the **test tenant's** partition during the outage exercise, and (ii) the fail-closed `ScopedOutageDegradationBreach` pre-commit audit envelope on a breach.
- **Tenant isolation by construction (NFR9a, NFR59).** The validation runs under a test tenant and every durable store is tenant-partitioned, so the injected outage and its recovery land only in the test tenant's partition. The production-tenant identity for the no-mutation assertion is `!ReplayTenantPolicy.IsTestTenant(tenantId)`. Never weaken partitioning to "make the outage observable".
- **Boundary (NetArchTest-enforced).** All new types are `internal` to `.Server` (`ScopedOutageDegradationEvaluator`, `ScopedOutageDegradationValidationCoordinator`, `ScopedOutageDegradationReport`, `ScopedOutageDegradationOutcome`, `ScopedOutageDegradationMeasurement`, `ScopedOutageDegradationVerdicts`, `ScopedOutageDependencies`, `ScopedOutageScopes`, `IScopedOutageInjectionDriver`, `DeferredScopedOutageInjectionDriver`). No `.Contracts`/`.UI`/`.Cli`/`.Mcp` reference. Confirm `DependencyDirectionFitnessTests` / `AdapterBoundaryFitnessTests` stay green.
