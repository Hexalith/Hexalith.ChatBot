## What Went Well

- The CommandGateway spine scaled across intake, participant resolution, scoring, S2 decisions, correction, propagation, and retry without introducing a parallel mutation path.
- The team repeatedly enforced metadata-only evidence: no raw email body, raw provider payload, unauthorized project names, secrets, or upstream PII in durable events, projections, status, or user-facing errors.
- Review findings were concrete and valuable. Examples include mailbox tenant-scope hardening, participant ambiguity handling, auto-association invariant revalidation, correction authorization, correction propagation idempotency, DAPR-backed association projection storage, and retry execution through the real dispatcher/aggregate path.
- The UI work stayed bounded to governed primitives and client facades. S2 added review, evidence comparison, disabled reasons, localization, and accessibility behavior without bypassing server ownership.
- Reliability became visible. Duplicate suppression, retry/failure metadata, operator alerts, and durable operation status gave later epics a clearer status substrate.

## Challenges

- Contract wire-token behavior needed repeated attention. Enum and OpenAPI drift risk appeared until tests covered direct and nested serialization.
- Projection translators were easy to write from assumptions instead of actual domain event payloads. Decision, correction, and propagation stories all benefited from event-specific projection tests.
- Some paths initially passed through fakes while the real EventStore dispatcher/aggregate path was incomplete. Story 2.9's retry review exposed this clearly.
- Correction propagation implemented durable lifecycle and coordinator/activity seams, but not a hosted Dapr Workflow runtime binding. Documentation must keep that distinction explicit.
- Story and doc hygiene remained an active concern: file lists, topology language, and implementation claims needed reconciliation after review fixes.

## Key Lessons

1. Association safety requires aggregate-side revalidation in addition to gateway and orchestrator checks.
2. New public enums need stable wire-token tests before review.
3. Projection translators should be tested from real domain event families, not inferred read-model shape.
4. A retry feature is incomplete until the allowlist, idempotency composer, dispatcher, aggregate handler, status store, and UI status path all execute coherently.
5. User-visible workflow state needs durable read stores in live topology.
6. Documentation must distinguish implemented seams, runtime bindings, and production readiness claims.
