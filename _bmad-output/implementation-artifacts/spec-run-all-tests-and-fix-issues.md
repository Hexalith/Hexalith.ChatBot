## Design Notes

The root solution includes selected production dependencies from submodules but no submodule test projects. “All tests” therefore means all 13 ChatBot-owned projects plus the strict ChatBot topology/browser execution; testing every independent repository under `references/` would be a separate multi-repository goal.

Tier-3 endpoint isolation must replace fixed launch-profile assignments only on the exact sidecar-backed project `http` endpoints. Create the builder first so allocation can exclude every concrete port/target-port declared by unselected endpoints. Reserve all replacement ports at once, with bounded and distinct candidate selection, on IPv6 dual-mode wildcard sockets when supported and IPv4 wildcard sockets when IPv6/dual-mode is unavailable; reject invalid ports, keep every reservation open while the application model is built, set each selected non-proxied endpoint's `Port` and `TargetPort` to the same reserved value, and release immediately before application startup. Retain the resource-to-reserved-port mapping and start exact-resource log watchers before validating all four resources concurrently under one shared five-minute deadline. A selected resource is ready only when it is Running with null/healthy health, exposes exactly its assigned active `http` URI, and a TCP connection to that URI/port succeeds; any terminal or unhealthy state fails promptly, and all four resources are rechecked together before returning success. For terminal retry, a single captured log line must contain address-bind evidence (including Windows access-denied wording) and the exact selected numeric port. For thrown exception graphs, the same bind-plus-exact-port rule applies within one root-to-leaf branch; resource-name matching and aggregate-sibling evidence are forbidden. Cancellation never retries. A retry uses an entirely fresh builder/reservation set, is bounded to two total attempts, always disposes the failed attempt even if classification fails, and if attempt two creation/start/validation fails, rethrows that failure with the first correlated failure attached; classification/cleanup errors remain attached to their original failure. All unrelated failures propagate unchanged. Deterministically exercise concurrent terminal detection, pre-bind Running/URL rejection, log-ingestion and wrong-port behavior, false-correlation rejection, cancellation, second-attempt diagnostics, duplicate/invalid/bounded candidates, and cleanup without an OS release/rebind gap. Do not mutate container, proxied, HTTPS, management, debug, or unrelated project endpoints, and do not extend readiness timeouts.
