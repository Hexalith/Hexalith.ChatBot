## What Went Well

- **Guard-first sequencing worked again, end-to-end.** Story 13.1 made the page-composition debt measurable, shrink-only, and build-blocking before any migration started. The three-ratchet pattern per allowlist — missing-path assertion, offender-outside-allowlist failure, and stale-entry assertion — reliably forced each subsequent story to delete its entries and proved the migration bit (a reverted mutation test confirmed the ratchet fails when an entry is dropped prematurely).
- **The overlap was fixed structurally, not with CSS.** `FcPageHeader` emits `<header role="presentation">` inside the shell's single `#fc-main-content` landmark, so it never competes with `FrontComposerShell`'s 48px banner — matching the no-overlap `Hexalith.Tenants.UI` reference. The defect was a composition gap, not a styling bug.
- **Disciplined, judgment-driven component choices.** The team used `FluentStack`/`FluentText` for fixed key-value metadata (to preserve queryable `data-chatbot-*`/`role="row"` markers) and reserved `FluentDataGrid`/`FluentCard` for genuinely tabular/repeated data (`/operational-dashboards`). The reconciliation pattern for grids that expose no per-row attributes — a parallel sibling row-marker `@foreach` mirroring Tenants' `AuditDataGrid` — kept machine-queryable tokens alive without abandoning the grid.
- **Governed semantics and accessibility were preserved throughout.** Stable `HeadingId`/`aria-labelledby` focus targets, focus-landing ids (`operation-outcome-title`), forced-colors/reduced-motion anchors, non-color status cues, and EN+FR localization were re-verified per story; no new localization keys were required for the layout work.
- **`Hexalith.Tenants.UI` as the canonical reference paid off.** `MyTenantsPage.razor`/`TenantAuditPage.razor` and `DomainUiFluentConformanceTests` anchored every composition decision, including the intentional dropping of the nested `region` landmark in favor of the single shell `<main>`.
- **The real-render gate (13.9) did exactly the job it was created for.** It surfaced a production defect that all of Epics 10/12/13's source-scan and static-fixture checks had missed.

## Challenges

- **The headline defect: the live app was missing the scoped CSS bundle, and a coarse gate passed it anyway.** `Components/App.razor` linked only `css/chatbot.tokens.css`, never the scoped `Hexalith.ChatBot.UI.styles.css` bundle that `@import`s the Fluent UI + FrontComposer.Shell bundles carrying the `FluentLayout` CSS grid. The live DOM therefore rendered with shell-header overlap, hard-bordered boxes, and a collapsed `.fluent-layout` — the very defects Epic 13 set out to remove. Worse, Story 13.9's *first* pass shipped 42 screenshots that literally depicted the broken layout while the story claimed they proved the opposite, because the assertions only checked one element's vertical position and one element's border. The reviewer applied the "run the app and look" lesson, opened the screenshots, probed the live host, and traced the cause. Fixed: `App.razor` now links the scoped bundle; the gate was hardened with a per-surface `.fluent-layout` `display:grid` assertion; all 42 screenshots were regenerated against the corrected render. The `Hexalith.Tenants.UI` reference app had always linked the scoped bundle — ChatBot's did not.
- **Blazor Server culture must ride a cookie, not the query string.** The initial real-render run failed because `?culture=fr` set only the prerender; the interactive `_blazor` WebSocket circuit carries no query string and reverted to default `en`, making FR and EN captures byte-identical. Fixed by setting the `.AspNetCore.Culture` cookie so `CookieRequestCultureProvider` applies to both the prerender GET and the live circuit.
- **The real-render harness needed a real host.** The default in-memory `TestServer` from `WebApplicationFactory<Program>` is unreachable to a Playwright browser socket; `LiveChatBotUiHost` stands up a second real Kestrel host on `127.0.0.1:0` with a test-only `IChatBotClient → FakeChatBotClient` (metadata-only) as the sole override.
- **Sandbox limitation deferred live verification to the end.** A flaky Aspire/DAPR sandbox and the pre-existing Tier-3 403 TenantMissing meant per-story live visual verification (AC4 in 13.2, AC3 in 13.3, AC6 in 13.4/13.5) could not run; all stories accepted structural + Tenants-parity verification as the binding interim gate and deferred the real-render screenshot pass to 13.9. This was sound — but it concentrated the only true visual oracle into one story, where the scoped-CSS defect was waiting.
- **Recurring commit-hygiene and dev-bookkeeping findings.** Multiple stories carried a MEDIUM/LOW about process rather than code: out-of-order orchestration pre-committed migrations into misleadingly-titled commits (13.2/13.7, including 5 bundled submodule pointer bumps), empty Dev Agent Records set to `review` (13.4), an undocumented coupled E2E test change against a "do not edit fixtures" fence (13.6), and pre-existing dirty submodule pointers (EventStore/Timesheets) that had to be kept out of each commit (13.8/13.9).
- **Planning prose under-counted reality, repeatedly.** Guard seeds were higher than the proposal prose (`chatbot-page` 2→6, `chatbot-command-bar` 3→4 — multi-class hits the prose missed); the "25 definition-list surfaces" was really 23 owned by 13.4 + 2 page-owned; the audit form was "13 fields" in prose but 12 in reality. Source scan was authoritative every time.

## Key Learnings

1. **Source-scan guards and static fixtures are necessary but not sufficient — you must run the real app and look.** This is the decisive epic lesson. Empty allowlists, green contract tests, and passing static-fixture E2E all coexisted with a fully broken live layout. Only `Page.GotoAsync` against a running host, plus a human/AI reviewer actually opening the screenshots, caught the missing scoped-CSS bundle.
2. **A verification gate is only as strong as its assertions.** Coarse geometry checks (one element's top, one element's border) passed a collapsed layout. Gates that re-verify a composition must assert the load-bearing invariant directly — here, `.fluent-layout` resolving to `display:grid` proves the scoped bundle actually loaded.
3. **Guard-first ratcheting is repeatable and effective** when the guard is non-vacuous, exact (whole-token/word-boundary regexes — `chatbot-page` is a prefix of `chatbot-page-header`/`-title`), and shrink-only with a stale-entry assertion.
4. **Preserve machine-queryable and accessibility contracts when changing presentation.** `FluentDataGrid` exposes no per-row arbitrary attributes; the sibling row-marker `@foreach` keeps `data-chatbot-*`/`role="row"` selectors and aria-live announcements alive. Don't rewrite semantic markup just to look more "componentized" when the existing roles are the safer test/a11y contract (carried directly from the Epic 12 learning).
5. **Web-framework runtime details bite at the rendering boundary.** Blazor Server culture must be carried by cookie across the interactive circuit; scoped-CSS bundles must be explicitly linked in `App.razor`; the test host must be a real socket, not in-memory. These only surface when the real app runs.
