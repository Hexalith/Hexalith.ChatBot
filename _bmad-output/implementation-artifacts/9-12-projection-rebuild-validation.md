# Story 9.12: Projection rebuild validation

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an operations owner,
I want projection rebuilds validated from immutable source records and audit history,
so that derived state can be recovered deterministically without mailbox re-ingestion.

## Acceptance Criteria

1. **Derived projections rebuild from immutable source records + audit history within the 4-hr target for the baseline validation dataset, without mailbox re-ingestion (NFR57).**
   **Given** the baseline validation dataset (a test-tenant's derived projections built from its immutable source records and WORM audit history),
   **When** the projection-rebuild validation runs for that dataset,
   **Then** the `ProjectionRebuildValidationCoordinator` drives a rebuild **from immutable source records + audit history only** (never a mailbox/Graph re-ingestion) and the pure `ProjectionRebuildEquivalenceEvaluator` compares the **measured rebuild duration** against the canonical **4-hr** target, returning a `DurationWithinTarget` boolean. The 4-hr bound is the **single source of truth already defined once** as `RecoveryTargets.MaxRto` (Story 9.11) — NFR57's rebuild-duration target is the same 4-hr recovery-time bound; **never re-type `4`/`TimeSpan.FromHours(4)`** for this story. A grep must confirm no new file hard-codes `4` for the rebuild target.
   - **Rebuilds from the immutable source-of-record, not from mailboxes (the defining NFR57 property).** The rebuild input is (a) the tenant's **immutable source records** (`ProjectConversationSourceEmailView` — the retained `source-email-metadata` data class, Story 9.7) and (b) the tenant's **WORM audit history** (`IWormAuditStore.EnumerateChain(tenantRef)`, the D4 source of truth). It does **not** call Graph, does **not** re-fetch any mailbox, and does **not** depend on any live upstream — this is exactly the "recover derived state without mailbox re-ingestion" guarantee. The driver seam's contract documents this; the test fake honors it (no mailbox/Graph dependency).
   - **The rebuild is by construction a test-tenant operation (no production mutation).** Like replay (Story 9.4) and the continuity drill (Story 9.11), the validation rebuild runs against a **test tenant** resolved by the single authoritative `ReplayTenantPolicy.IsTestTenant` predicate; it mutates **no** production-tenant durable projection state. A production-tenant target fails closed to `unmeasurable` and the driver is never invoked. **Do not** add a "rebuild flag on a production tenant."
   - **Fail-safe over fabrication (Epic 8/9 no-fabrication doctrine).** A validation that **cannot complete** — the driver throws, the rebuild never finishes, or the snapshots/durations are unavailable — yields `unmeasurable` (a breach signal), **never** a fabricated `equivalent`/within-target. Mirror `AuditCompletenessMeasurement.Unmeasurable(...)`, `ContinuityDrillReport.Unmeasurable(...)`, and `ReplayIsolationStatus.Unknown` exactly.

2. **A rebuilt projection is equivalent to the pre-rebuild projection (deterministic rebuild) for the baseline validation dataset (NFR57).**
   **Given** a rebuilt projection and the pre-rebuild projection for the same baseline dataset,
   **When** they are compared,
   **Then** the pure `ProjectionRebuildEquivalenceEvaluator` diffs the two **metadata-only structural snapshots** (an ordered set of per-resource `ProjectionResourceDigest(ResourceId, StructuralStateToken)`) and returns `equivalent` **iff** they cover the same resource-key set, every per-resource `StructuralStateToken` matches, **and** the `ProjectionSchemaVersion` of the rebuilt snapshot matches the pre-rebuild snapshot; otherwise `divergent`. A `divergent` verdict means the rebuild is **non-deterministic** — the serious NFR49a/invariant-#11 breach (it makes evidence snapshots / approval records non-reproducible) — and records the first-diverging resource as a safe bounded `FirstDivergingResourceLocator` plus a `projection_diverged` deviation token.
   - **Determinism is the core proof (architecture invariant #11 — derived-state versioning & deterministic replay).** The rebuild must stamp the **projection schema version** in its output snapshot and use **as-of upstream resolution** (it must NOT re-query *current* Party/Folder/sibling-context data during the rebuild — that would make the rebuild diverge from the original as-of state). A schema-version mismatch between the pre-rebuild and rebuilt snapshots is divergence (the event-upcasting / schema-churn failure mode). The structural state token is the **same structural-digest discipline Story 9.2 already uses** (`AuditOperationReconstructor.ReconstructedOperationState.ResultingStateToken` and the `GovernedOperationView` structural fields — `SchemaVersion`, `SourceProvenance`, `DerivationKernelVersion`, `RedactionState`, `RetentionClass`, `SourceVersion`), never raw item content.
   - **The evaluator is pure and deterministic.** `ProjectionRebuildEquivalenceEvaluator.Evaluate(...)` takes no clock and does no IO; re-running it over the same two snapshots yields the same verdict and the same first-diverging locator. Snapshot comparison is order-independent on the resource-key set but the first-diverging locator is deterministic (compare in the pre-rebuild snapshot's stable key order).

3. **The rebuild runs tenant-scoped and produces no cross-tenant read or write (NFR9a, NFR59).**
   **Given** a validation rebuild,
   **When** it executes and completes,
   **Then** the rebuild produces **no cross-tenant read or write**: it is tenant-scoped to the validation's test tenant by construction (NFR9a — every durable store — `IWormAuditStore.EnumerateChain(tenantId)`, the source-record projection, the derived/projection store — is tenant-partitioned, so the rebuild lands only in the test tenant's partition); and the `ProjectionRebuildReport`, the operator alert payload, the audit envelope, and every emitted token are metadata-only safe bounded tokens carrying **no** foreign-tenant identity, raw item content, recipient PII, prompt, or payload.
   - **Reuse the cross-tenant leakage harness — do NOT build a new no-leak path.** Extend the `CrossTenantLeakageScanner` / `CrossTenantLeakageCorpus` conformance suite (Story 1.12) to assert no foreign-tenant sentinel survives serialization of `ProjectionRebuildReport`, the `ProjectionRebuildOutcome`, the `ProjectionResourceDigest`, and the `ProjectionRebuildValidationFailed` audit envelope. **Use a neutral, non-sentinel tenant token** (e.g. `tenant-projection-rebuild`) — `tenant-alpha` is the Story 1.12 corpus `BoundTenant` sentinel and `tenant-beta` the `ForeignTenant` (the 9.8/9.9/9.10/9.11 leakage-scan gotcha).
   - **No unauthorized / no production state mutation.** The validation is a system/Worker-origin recovery exercise, not a governed command; it performs no governed write outside its test tenant. The coordinator asserts the production-tenant projection stores are unchanged across a validation run (the Story 9.4/9.11 "no production project state mutated" assertion is the template).

4. **The rebuild produces a validation report (dataset, duration vs the 4-hr target, diff result) and, on a breach, fails closed audit-then-alert (NFR57).**
   **Given** a validation rebuild completes,
   **When** it is recorded,
   **Then** the run produces a metadata-only `ProjectionRebuildReport` carrying: the `DatasetRef` (the baseline validation dataset id), `StartedAtUtc` / `EndedAtUtc`, the `MeasuredRebuildDuration` (`TimeSpan`), the `DurationWithinTarget` boolean (the duration-vs-4-hr diff), the `Verdict` (`ProjectionRebuildVerdicts` token — `equivalent` / `divergent` / `unmeasurable`), the `ResourcesCompared` count, a bounded `Deviations` list (safe reason tokens), the `FirstDivergingResourceLocator` (safe token or null), the `ProjectionSchemaVersion`, the test-tenant `TenantRef`, the `CorrelationId`, and a `ReasonCode`. This report **is** the NFR57 validation evidence artifact (dataset + duration-vs-target + diff result).
   **And** on a **breach** — a `divergent` verdict (determinism failure), an `unmeasurable` validation (fail-safe), **or** `DurationWithinTarget == false` (a recovery-time miss) — the coordinator does **fail-closed audit-then-deliver**: it writes the `AuditEnvelopeFactory.ProjectionRebuildValidationFailed` pre-commit envelope **before** emitting exactly one `OperatorAlertKind.ProjectionRebuildValidationFailed` alert through the existing `IOperatorAlertSink`. The `Deviations` enumerate `projection_diverged` / `rebuild_duration_exceeded` / `rebuild_incomplete` as applicable.
   - **Three distinct breach dimensions — keep them distinct in the outcome.** `divergent` (non-deterministic rebuild) is the **serious** breach: it undermines NFR49a evidence reproducibility (invariant #11), analogous to a 9.4/9.5 isolation breach — a release gate that cares about determinism asserts `Divergent == 0 && Unmeasurable == 0`. A **duration overrun** (`DurationWithinTarget == false`) is a recovery-time **miss** — analogous to the Story 9.11 RPO/RTO miss: a recorded deviation that is a recalibration/follow-up signal, **not** by itself a determinism failure (a deterministic-but-slow rebuild is `equivalent` with `DurationWithinTarget == false`). `unmeasurable` is the **fail-safe** breach (no evidence produced). The `ProjectionRebuildOutcome` keeps `Equivalent` / `Divergent` / `DurationExceeded` / `Unmeasurable` distinct so a gate asserts the dimension it cares about. Never collapse `divergent` or `unmeasurable` into `equivalent`, and never let a duration overrun silently pass.

### Cross-cutting requirements that hold for every AC

- **This is a validation-harness story, not a governed-command story.** It is the direct sibling of the Story 9.2 completeness measurer, the Story 9.4/9.5 isolation probes, and the Story 9.11 continuity drill — a **pure evaluator + an injectable coordinator + a structured outcome + fail-closed audit-then-deliver + a metadata-only report**, all server-internal in `.Server/Audit/`. There is **no** `IChatBotCommand`, **no** `ChatBotSpineCommandAllowlist` entry, **no** `ParticipantAuthorizationStage` gating block, and **no** `.Contracts` change. Do not add any of those — copying the 9.7–9.10 governed-command shape here is the primary anti-pattern to avoid.
- **Inert-control-floor honesty (the defining constraint — say it explicitly in Completion Notes).** What ships and is fully built+tested: the `ProjectionRebuildVerdicts` token set, the `ProjectionResourceDigest` structural-snapshot record, the pure `ProjectionRebuildEquivalenceEvaluator`, the `ProjectionRebuildReport` artifact + `Unmeasurable` factory, the `ProjectionRebuildValidationCoordinator` (run-validation + sweep, fail-closed audit-then-alert, deviation recording, test-tenant-by-construction, no-production-mutation assertion), the `ProjectionRebuildOutcome` gate contract, the new `OperatorAlertKind.ProjectionRebuildValidationFailed`, and the `AuditEnvelopeFactory.ProjectionRebuildValidationFailed` envelope. **Deferred** (documented seams, exactly like Story 9.4's deferred replay driver, 9.11's deferred fault-injection runtime, and 9.1/9.2/9.4/9.5/9.11's deferred periodic scheduler): (a) the **live rebuild driver** that actually replays a tenant's immutable source records + WORM history into a fresh projection store against a deployed AKS/Aspire environment — modeled behind an `IProjectionRebuildDriver` seam that the coordinator consumes (tests drive it with a deterministic scripted fake returning the two snapshots + measured duration); (b) the periodic scheduler / release-gate wiring (no always-on `BackgroundService`). The evaluator, coordinator, report, alert path, and gate outcome are real and tested; only the live infra rebuild driver and the periodic trigger are deferred. **Never let a deferral read as "rebuild/recovery is unproven/unmeasured"** — the equivalence semantics, the duration-vs-target check, and the fail-closed evidence path are all real and tested against the driver seam.
- **Fail-safe / no-fabrication floor (Epic 8/9 spine doctrine).** Prefer `unmeasurable` over a fabricated `equivalent`. A validation whose driver throws, whose rebuild never completes, or whose snapshots/durations are unavailable is `unmeasurable` (a breach signal that fail-closed-audits-then-alerts), never a silent pass. Mirror `AuditCompletenessMeasurer` (`Unmeasurable`, never invented 100%), `ContinuityDrillCoordinator` (catch ⇒ unmeasurable), and `AuditChainVerificationCoordinator` (incomplete → breach).
- **Metadata-only / no-leak floor (NFR2, NFR42, NFR45).** Every report field, outcome field, digest field, deviation token, alert payload, locator, and verdict token is an `AuditMetadata`-safe bounded token (ASCII alnum + `.-_:@|`, marker-ban on `secret`/`password`/`bearer`/`token`/`exception`/file-extension sentinels). The report records **no** raw email content, recipient addresses, subject, body, prompts, payloads, or vector/embedding values — only safe tokens, the duration, counts, and bounded reason codes. Reuse `AuditMetadata.SafeOptionalToken` / `IsSafeStableIdentifier` for any locator. Metric/alert dimensions stay low-cardinality (`tenant` + bounded `verdict`/`reason` only — never ids/correlation in a metric tag).
- **Read-mostly / out-of-band — the commit path is untouched (D4, two-phase audit, NFR15a).** The validation rebuilds out-of-band and reads the WORM chain / source records; it adds **no** commit-time gate and never mutates the audit chain. Its only writes are (i) into the **test tenant's** projection partition during the rebuild exercise, and (ii) the fail-closed `ProjectionRebuildValidationFailed` pre-commit audit envelope on a breach. The WORM chain is the source of truth and the rebuild validates the D4 "chain/state rebuilt from the log on recovery" property — it does not weaken it.
- **Tenant isolation by construction (NFR9a, NFR59).** Rebuild is isolated **because the validation runs under a test tenant** and every durable store is tenant-partitioned. Never weaken partitioning to "make the rebuild work"; the rebuild works *through* it. The production-tenant identity for the no-mutation assertion is `!ReplayTenantPolicy.IsTestTenant(tenantId)`.
- **Boundary (NetArchTest-enforced).** All new types are `internal` to `.Server` (`ProjectionRebuildEquivalenceEvaluator`, `ProjectionRebuildValidationCoordinator`, `ProjectionRebuildReport`, `ProjectionRebuildOutcome`, `ProjectionResourceDigest`, `ProjectionRebuildMeasurement`, `ProjectionRebuildVerdicts`, `IProjectionRebuildDriver`, `DeferredProjectionRebuildDriver`). No `.Contracts`/`.UI`/`.Cli`/`.Mcp` reference. Confirm `DependencyDirectionFitnessTests` / `AdapterBoundaryFitnessTests` stay green.

### Architecture constraints (must follow)

- **NFR57 (projection rebuildability).** Derived projections must be rebuildable from immutable source records + audit history within the default 4-hr target for the baseline validation dataset, **without mailbox re-ingestion**, and the rebuild must be deterministically equivalent to the pre-rebuild projection. This story IS that validation harness. [Source: epics.md:267, 2588-2608; architecture.md:85 (recovery), 144-147 (rebuild-and-diff), 156-161 (invariant #11)]
- **Invariant #11 — derived-state versioning & deterministic replay (the determinism backbone).** ChatBot owns derived state rebuilt by replaying events; a projection schema change must map old events → new schema (event upcasting), or replay produces state divergent from live — making evidence snapshots / approval records non-reproducible and undermining NFR49a. The rebuild must stamp the projection schema version in replay traces, use **as-of upstream resolution** (do not re-query *current* Party/Folder data during rebuild), and the equivalence evaluator treats a schema-version mismatch as divergence. [Source: architecture.md:156-161]
- **NFR59 (no cross-tenant leakage / no unauthorized mutation during recovery).** Rebuild is tenant-scoped by construction; the validation asserts no cross-tenant read/write and no production mutation. [Source: epics.md:2604-2606; architecture.md (NFR58-59)]
- **D4 / two-phase audit (fail-open-then-reconcile).** The post-commit WORM chain is fail-open-then-reconcile: the event log is the source of truth and the chain/state is rebuilt from it on recovery — the validation proves this rebuild is deterministic; it adds **no** commit-time gate. [Source: architecture.md:369-372]
- **Epic 8/9 no-fabrication doctrine.** Prefer `unmeasurable` over a fabricated `equivalent`; an incomplete validation is a fail-safe breach signal, never a silent pass. [Source: src/Hexalith.ChatBot.Server/Audit/ContinuityDrillReport.cs; AuditCompletenessMeasurer.cs]
- **NFR9a (tenant isolation by construction).** The validation runs under a test tenant; every durable store is tenant-partitioned, so the rebuild lands only in the test tenant's partition. [Source: src/Hexalith.ChatBot.Server/Audit/ReplayTenantPolicy.cs; IWormAuditStore.cs]
- **NFR2 / NFR42 / NFR45 (metadata-only / no-leak).** Report, outcome, digest, alert, and every token are `AuditMetadata`-safe bounded tokens; the duration is integer seconds, counts are integers, flags are booleans; no raw content, no embedding/vector values. [Source: src/Hexalith.ChatBot.Server/Audit/AuditMetadata.cs]
- **Boundary (NetArchTest-enforced).** All new types `internal` to `.Server`; no `.Contracts`/`.UI`/`.Cli`/`.Mcp` reference. [Source: architecture.md:577-585; tests/Hexalith.ChatBot.Architecture.Tests/Fitness/AdapterBoundaryFitnessTests.cs]
