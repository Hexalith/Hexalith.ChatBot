## What Went Well

- The CommandGateway spine absorbed new domain work without parallel admission logic. Mailbox intake, association scoring, participant resolution, decisions, correction, and retry all stayed on the governed command path.
- Metadata-only evidence became a consistent implementation pattern. Stories repeatedly avoided raw message body, raw provider payload, unauthorized project names, and upstream PII in durable events, projections, and user-facing responses.
- Reviews found real issues and converted them into regression tests. High-value fixes included participant ambiguity handling, auto-association invariant revalidation, decision-event projection reconstruction, duplicate correction acknowledgements, and retry execution through the real EventStore dispatcher.
- The S2 surface stayed within its intended scope while still proving the UX contract: candidate review, evidence comparison, focus-reachable disabled reasons, localization, reduced-motion/forced-colors support, and metadata-only service boundaries.
- DAPR-backed production stores were expanded where user-visible state required durability. Association routing/progress projections and operation status no longer rely only on in-memory stores in the live topology.

## Challenges

- Contract wire tokens were fragile until Story 2.4 introduced `JsonEnumMemberStringConverter<TEnum>` coverage. The system initially risked writing CLR enum names instead of stable API tokens.
- Projection translators assumed earlier event shapes. Story 2.6 showed that decision events needed explicit metadata reconstruction rather than reuse of previous candidate collections.
- Some paths were initially over-proven by fakes. Story 2.9 review caught retry admission that looked correct through gateway tests but did not yet execute through the real dispatcher and aggregate path.
- Correction propagation delivered a DAPR-ready coordinator/activity seam and durable lifecycle events, but the current code does not wire the Dapr Workflow SDK/runtime. Planning docs that say the runtime is already hosted need clarification.
- Story records and docs remained vulnerable to implementation drift. File lists, topology wording, and acceptance references needed repeated reconciliation against the actual code.

## Key Insights

1. Association safety depends on aggregate-side revalidation, not just gateway or scorer correctness.
2. Stable wire tokens need converter-level tests for direct and nested payloads.
3. Projection code must be written from actual domain event payloads, not from assumptions carried forward from previous story views.
4. A retry feature is not complete until the real dispatcher and aggregate path execute it.
5. User-visible workflow state needs durable DAPR-backed stores in the live topology, not just in-memory test substitutes.
6. Planning docs should distinguish an implemented coordinator seam from a hosted Dapr Workflow runtime.
