## What Went Well

### The product promise became concrete

Project Workspace changed the application's center of gravity from an operational queue to a project-centered conversation, context, files, and governed interaction surface. The selected workspace and direct project-conversation route reuse the same component rather than forking behavior.

### The governance spine survived substantial UI and runtime change

User messages use the metadata-only `RecordProjectConversationMessage` command. Ask-AI requests use the existing Epic 4 proposal and approval path. Stop/Cancel uses `CancelAiResponseGeneration`. All writes remain behind `IChatBotClient.SubmitAsync`, `ChatBotSurfaceOrigin.Ui`, and CommandGateway. Durable rows and terminal states come from typed server reads rather than optimistic UI claims.

### Existing domain surfaces were reused

The implementation preserved the S1 conversation stream, S2 association review, S3 approval review, operational queues, audit investigation, proposal rendering, and approval rendering. FrontComposer remained the single shell and provider owner while ChatBot components remained governed body content.

### Accessibility and localization were designed into the interaction model

The workspace and composer added explicit localized states, keyboard-safe text entry, validation focus, reachable disabled reasons, stable Stop placement, server-verified Stop announcements, reduced-motion behavior, non-color status cues, and English/French parity.

### Review eventually demanded executable reality

Story 10.6b did not close on contracts and reducers alone. Review exposed the missing producer and receiver, the live topology disproved the initial DAPR relay, and the implementation pivoted to a ChatBot-owned tenant-grouped SignalR hub. A real `HubConnection` test proved delivery and tenant isolation. Additional review hardened JWT-configured fail-closed behavior, reconnect re-query, and benign duplicate handling.

### Architecture provenance was preserved

The streaming ADR records the metadata-only nudge model, server verification floor, Stop/Cancel semantics, reconnect behavior, rejected content-streaming alternative, expected tests, and the final ChatBot-owned hub implementation note. Architecture and README documentation now reflect the delivered transport.

## Challenges and Growth Areas

### Browser fallbacks repeatedly created false confidence

Stories 10.1, 10.4, and 10.5 each contained a browser-path defect masked by a fallback or source-only assertion. Story 10.6b also needed its nominal streaming E2E replaced with real rendered behavior. Later Epics 12 and 13 confirmed the wider pattern: static fixtures and source scans can be valuable supporting evidence, but they cannot establish the primary browser or runtime claim.

### Shell adoption was under-specified

Epic 10 correctly established shell ownership but did not operationalize Fluent component-level conformance or FrontComposer page-level composition. The acceptance criteria allowed the custom token bridge to be "retired or reconciled," and tests guarded wrapper ownership rather than the full component tree. Epic 12 later removed raw interactive controls and the parallel CSS primitive layer. Epic 13 later replaced hand-built page chrome and discovered that the live application did not load its scoped CSS bundle.

### Story records sometimes got ahead of executable behavior

Reviews found stale test counts, incomplete File Lists, inaccurate scope claims, checked tasks contradicted by the diff, and build or verification claims that did not match the current tree. Story 10.6a required correction of a false empty-diff claim and a missing expected-tests handoff. Story 10.6b initially marked the transport task complete while no producer or receiver existed.

### The initial streaming topology assumption was wrong

The first Story 10.6b transport attempted to reuse an EventStore relay. A live topology run showed incompatible pub/sub component names, a compile-time EventStore topic, and disabled EventStore SignalR. The ChatBot-owned hub pivot was the correct result, but the mismatch should have been discovered through a topology inventory before implementation.

### One cancellation integrity gap remains deferred

The Stop/Cancel handler is tenant-bound and its read result is project-authorized, but it does not verify that the target response and generation exist, belong to the selected project/conversation/session, remain active, or match the expected source version. This is bounded integrity debt rather than a confidentiality breach. Full correction requires a server-owned generation-session lifecycle.

### Aggregate tracking continued to trail story reality

Every Epic 10 story was done while the epic remained `in-progress`. Epic 11 has the same aggregate mismatch even though its stories and retrospective are done. This repeats the tracking drift called out by earlier retrospectives.

## Key Learnings

1. **Run the real application and prove the load-bearing invariant.** Browser availability, live asset loading, hub delivery, authorization, and distributed topology cannot be inferred from strings or isolated handlers.
2. **Define UI adoption in layers.** Shell ownership, Fluent component conformance, FrontComposer page composition, scoped asset loading, and real rendered behavior are distinct acceptance dimensions.
3. **A fallback is not equivalent evidence.** It may keep diagnostics useful when an environment capability is absent, but it cannot establish a runtime claim the primary path did not execute.
4. **Review must trace the complete production path.** Contracts, reducers, and direct-handler tests were green while the producer, receiver, callback, or real route was absent or incorrect.
5. **Story integrity needs a mechanical gate.** Repeated File List, test-count, status, and checked-task drift demonstrates that manual reconciliation is not a durable control.
6. **Architecture-changing epics need an explicit runtime-seam handoff.** Commands, callbacks, queries, projections, real-time channels, authorization, hosting, DataProtection, external resources, and their regression tests must be enumerated.
7. **Cross-epic structural debt closes only when it becomes explicit scope.** Epic 12 and Epic 13 succeeded because they started with shrink-only governance guards and dedicated remediation stories.
8. **Release readiness must test the roadmap against the product promise.** Epic 9 declared the roadmap finished before the governed interactive surface and shell adoption were recognized as required MVP work.

## Epic 11 Historical Handoff Assessment

Epic 11, Minimal Technical Layer - DomainService SDK Host Adoption, has already been implemented. The retrospective therefore assessed the handoff against actual outcomes.

Epic 10 provided a strong behavioral and safety baseline, but the handoff should have explicitly inventoried:

- CommandGateway admission and the EventStore callback path.
- Project-conversation query and projection routes.
- The ChatBot-owned SignalR hub and authorization configuration.
- UI service discovery without a Dapr sidecar.
- DataProtection requirements for protected admission markers.
- Public UI, CLI, MCP, and generated-client compatibility.

Epic 11 preserved public behavior and reduced the host successfully, but review discovered double-admission risk on the real callback path, shared DataProtection requirements, and a platform-composition API that could not express ChatBot's dedicated Dapr resources. The retained local AppHost shim and later security-helper story were defensible corrections.

No retroactive Epic 11 plan update is required because the epic is complete and absorbed these discoveries. The standing improvement is to require a runtime-seam manifest and live-path regression matrix between architecture-changing epics.

## Significant Discoveries

1. **The existing EventStore relay could not carry the chosen transport in the real ChatBot topology.** The streaming ADR and architecture now record the ChatBot-owned hub implementation while preserving the metadata-only projection-nudge model.
2. **FrontComposer shell ownership did not imply Fluent or page-layout conformance.** Epic 12 and Epic 13 were created and completed to close those distinct gaps.
3. **Live browser execution alone is insufficient if assertions miss the invariant.** Epic 13's first real-render pass captured a broken layout until the gate directly asserted the Fluent layout grid and the screenshots were inspected.
4. **Visible production asynchronous streaming still depends on a real asynchronous provider and generation-session lifecycle.** The current transport and safety foundation is complete, but that future capability cannot be claimed until the prerequisite exists and is verified.

The architecture and later epic plans already incorporate the first three discoveries. No current epic definition requires amendment. The fourth is a hard prerequisite for future production asynchronous-generation enablement.
