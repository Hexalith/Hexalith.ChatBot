# Story 3.11: Informational/actionable classification, AI-summary distinction, and review history

Status: done

<!-- Validation: create-story checklist applied 2026-06-01. -->

## Story

As an authorized contributor,
I want actionable items flagged, AI summaries visibly distinct from source evidence, and review history visible,
so that I never confuse AI interpretation with original facts and can see what humans decided.

## Acceptance Criteria

1. Given any email-derived S1 conversation item, when it renders, then it carries a visible `informational` or `actionable` badge sourced from explicit projected/contract fields, not from UI-only text parsing. The classification includes the kernel version, confidence score, safe source-evidence references, and stable explanation/message code needed to reproduce the result. [Source: _bmad-output/planning-artifacts/epics.md#Story 3.11; _bmad-output/planning-artifacts/prds/prd-Hexalith.ChatBot-2026-05-28/prd.md#FR26]
2. Given an `actionable` email item, when S1 renders it, then it surfaces the detected intent summary, detected action kind, source evidence offsets or safe evidence references, and the next-action affordance from the existing status-summary/next-action contract. This story may display and project the FR35 data contract, but must not implement task conversion, governed task creation, or Epic 4 AI action execution. [Source: _bmad-output/planning-artifacts/prds/prd-Hexalith.ChatBot-2026-05-28/prd.md#FR35; _bmad-output/implementation-artifacts/3-10-conversation-item-status-and-next-action.md#Scope-Boundaries]
3. Given AI-generated content on any S1 AI outcome or future AI summary-bearing item, when it renders, then source evidence is the default view and the AI-authored summary is opt-in/collapsible, visually and programmatically distinct with the label `AI summary`, non-color treatment, and a provenance string shaped as `Generated by <model+version> at <timestamp> from <source-evidence-IDs>`. [Source: _bmad-output/planning-artifacts/prds/prd-Hexalith.ChatBot-2026-05-28/prd.md#FR27; #NFR64]
4. Given an email, attachment, approval, AI action, or command conversation item, when S1 renders it, then visible human-review history is preserved as append-only metadata: reviewer actor/type, review action/decision, timestamp, surface origin, correlation/operation id when available, redaction state, and safe reason/message code. Superseded decisions remain history and are not mutated into the current row. [Source: _bmad-output/planning-artifacts/prds/prd-Hexalith.ChatBot-2026-05-28/prd.md#FR28; _bmad-output/implementation-artifacts/3-5-association-and-correction-decision-rendering.md#Current-State-To-Preserve]
5. Given restricted evidence, unauthorized resources, redacted review notes, hidden prompt/output/tool data, raw provider payloads, raw audit envelopes, or cross-tenant identifiers, when classification, AI-summary provenance, or review history renders, then the API/UI expose only safe metadata, localized safe labels, and redacted/unavailable explanations without confirming hidden resource existence. [Source: _bmad-output/planning-artifacts/prds/prd-Hexalith.ChatBot-2026-05-28/prd.md#NFR62; _bmad-output/planning-artifacts/architecture.md#Authentication--Security]
6. Given keyboard-only, screen-reader, forced-colors, reduced-motion, mobile, tablet, desktop, English, and French users, when badges, source-evidence/AI-summary sections, and review history render, then meaning survives without color alone, labels are localized, repeated regions have unique accessible names, critical words do not truncate, and source evidence remains reachable before AI summary content. [Source: _bmad-output/planning-artifacts/ux-designs/ux-Hexalith.ChatBot-2026-05-28/EXPERIENCE.md#Accessibility-Floor; #Localization; #Responsive--Platform]
7. Contract, OpenAPI, generated client, server projection/query mapping, UI service/model/component, localization, CSS, conformance, isolation, and E2E coverage prove classification, AI-summary distinction, review history, redaction, tenant isolation, accessibility, replay/order tolerance, and regression safety for the existing S1 stream. [Source: _bmad-output/planning-artifacts/architecture.md#Contract-Spine; #Requirements--Structure-Mapping]

### Architecture Guardrails

- Contract Spine remains the source of truth: OpenAPI 3.1 plus generated client plus contract tests. UI reads through `IChatBotClient`; S1 must not reference server projection internals. [Source: _bmad-output/planning-artifacts/architecture.md#Contract-Spine]
- Dependency direction remains `Contracts <- Client <- UI/Server`; UI, CLI, and MCP must not replicate gateway, projection, risk-classifier, audit, or status-store internals. [Source: _bmad-output/planning-artifacts/architecture.md#Architectural-Boundaries]
- ChatBot derived records carry tenant id, source provenance, derivation kernel/schema version, redaction state, retention class, source version, and correlation id. Classification and review-history fields must preserve this metadata posture. [Source: _bmad-output/planning-artifacts/architecture.md#Data-Architecture]
- Tenant authority comes from authenticated claims/context and access projections, never route/body/query values. Unknown, foreign, malformed, missing, ambiguous, stale, or unsafe contexts collapse to safe denial without confirming hidden resources. [Source: _bmad-output/planning-artifacts/architecture.md#Authentication--Security]
- Dapr pub/sub is at-least-once and projection reads are eventually consistent. Mapping/tests must tolerate duplicate and out-of-order projection events; never infer classification/review state from row counts.
- Use `System.Text.Json` shared enum-member behavior and existing OpenAPI/generated-client patterns. Do not add Newtonsoft.Json to hand-authored contracts, inline serializer options, or new serialization libraries.
- Keep repo-pinned dependencies: .NET SDK `10.0.300`, `net10.0`, warnings-as-errors, central package management, Blazor + Fluent UI v5 RC via FrontComposer, Fluxor, Dapr 1.17.x, Aspire 13.3.x, xUnit v3, Shouldly, NSubstitute, and existing Playwright fixtures. Do not upgrade packages for this story.

### UX And Accessibility Guardrails

- Classification badges, AI-summary/source-evidence sections, and review history are operational row affordances, not a new card feed or second conversation timeline.
- Evidence, risk, status, actor, and timestamp ordering must remain consistent. New affordances may sit below/within existing rows, but must not disrupt row header order.
- Source evidence is the default view. AI summaries are labelled and opt-in/collapsible; do not make AI-authored content look like source facts.
- Every workflow item has one primary next action. This story displays next action and review history only; it does not submit new actions.
- Plain-language labels precede raw IDs. Stable machine tokens, IDs, lifecycle states, status codes, message codes, source versions, and correlation IDs remain metadata and are not translated.
- Redacted/unavailable/disabled review or provenance details need reachable explanation text or an enabled "Why unavailable?" affordance. Tooltip-only explanations are insufficient.
- Historical review entries do not announce on initial load. Only new user-relevant changes may use polite, deduplicated live regions.
- Responsive layouts must retain classification, actor, state/status, safe next action, AI/source distinction, provenance, review decision, and recovery reason. French labels must not truncate critical state/action words.
- Forced-colors and reduced-motion behavior must cover badges, evidence/source/AI sections, review history, focus outlines, and collapsible controls.
