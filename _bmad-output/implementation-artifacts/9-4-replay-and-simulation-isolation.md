# Story 9.4: Replay and simulation isolation

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a QA/support engineer,
I want to replay representative mailbox events in full isolation,
so that investigation and testing never touch production or send external email.

## Acceptance Criteria

1. **Replay runs against a dedicated test tenant; outbound is intercepted and recorded, never sent; no production state mutated (FR95, FR95a, addendum §Replay Isolation).**
   **Given** a replay/simulation run,
   **When** executed,
   **Then** it runs against a **dedicated test tenant** whose outbound adapter is the **test-mode adapter**, which **intercepts every outbound send**, **records the would-have-sent envelope to the test-tenant's outbound-trace store**, and **returns success without contacting any external system**, mutating **no production project state**.
   - **Test-tenant selection is by construction, not by flag-on-a-production-tenant.** A tenant is a replay/test tenant iff it satisfies a single authoritative predicate (`ReplayTenantPolicy.IsTestTenant(tenantId)`); production tenants **never** resolve the test-mode adapter (addendum §Replay Isolation: "Production tenants do not have access to the test-mode adapter"). The adapter seam selects the test-mode sender **only** for a test tenant; for every production tenant the existing `IOutboundMailboxSender` resolution is **unchanged** (today `UnavailableOutboundMailboxSender`).
   - **The interception point is the existing send seam.** The only place the channel ref + authenticated `TenantBinding` meet immediately before the external adapter call is `AcceptedCommandDispatcher` for `ExecuteApprovedOutboundDraft` (`src/Hexalith.ChatBot.Server/Gateway/Stages/AcceptedCommandDispatcher.cs:761-871`, the `sender.SendAsync(...)` at line 848). The test-mode sender slots in **at that seam** (via tenant-aware `IOutboundMailboxSender` resolution) and returns `OutboundMailboxSendResult.Sent("adapter:mailbox-outbound-testmode")` after recording — so the aggregate's `AdapterStatus == "sent"` path runs **identically** to production, but **no external message leaves the boundary**.
   - **The would-have-sent envelope is metadata-only** (NFR2/NFR42 floor): it records the safe tokens already on `OutboundMailboxSendRequest` (`TenantId, ProjectId, DraftId, ApprovalId, SendId, RequesterId, SendActorId, SenderAuthorityClass, AdapterMode, CorrelationId`) plus the `ReplayRunId` and a UTC `RecordedAtUtc` — **never** recipient addresses, subject, or body content. It carries the same `AuditMetadata`-safe-token discipline as every other Epic 9 store.
   - **No production project state is mutated by a replay run.** Because the run executes under a test tenant, every durable write (`IWormAuditStore` chain, projection stores, idempotency store, outbound-channel control/history) is **already tenant-partitioned by construction** (NFR9a) and lands in the test tenant's partition only. The story must **assert** this (no production-tenant chain/projection grows during a replay run), not merely assume it.

2. **Replay events carry `replay_run_id`, are excluded from production audit queries by default, and are excluded from NFR50a completeness measurement (FR95a).**
   **Given** replay events,
   **When** audited,
   **Then** every audit envelope produced by a replay run carries a non-null **`replay_run_id`** (`AuditEnvelope.ReplayRunId`), is **excluded from production audit queries by default**, and is **excluded from NFR50a completeness measurement** (numerator and denominator).
   - **This story OWNS populating `ReplayRunId`.** Story 9.2 introduced the field, its v2 hash coverage, and `AuditReplayExclusion.IsReplayEnvelope`; Story 9.3 made the default-query exclusion real and testable. **Today every production audit record leaves `ReplayRunId` null** (see `AuditEnvelope.cs:23-29`). This story threads a replay-run context from the adapter boundary into `AuditEnvelopeFactory.Create` so that **all** envelopes emitted during a replay run (pre-commit, post-commit, duplicate-suppression, rejection, escalation — every factory method) carry the run's `replay_run_id`. The exclusion paths (`ComplianceAuditReadPolicy.Search`, `AuditCompletenessMeasurer`) already consume the marker via `AuditReplayExclusion.IsReplayEnvelope` — **do not re-derive or relocate the predicate**; this story makes those exclusions fire against **real** replay-marked records instead of the synthetic ones the prior stories asserted with.
   - **The marker must ride the same structurally-un-rewritable channel as `SurfaceOrigin`.** Thread `ReplayRunId` (nullable) on the immutable `ChatBotCommandSubmission` (alongside `CorrelationId`/`Origin`), carry it through the immutable `ChatBotGatewayContext`, and emit it from `AuditEnvelopeFactory.Create` (`AuditEnvelopeFactory.cs:597-638`) — so no downstream stage can forge, strip, or mutate it. A production submission leaves it null; a replay submission sets it once at the boundary.

3. **Nightly isolation probe asserts no replay record has ever appeared in any production tenant's outbound-trace store; probe failure gates M2 release (FR95a, addendum §Replay Isolation).**
   **Given** the nightly isolation probe,
   **When** it runs,
   **Then** it asserts **no replay run has ever produced a record in any production tenant's outbound-trace store**, and **probe failure gates the M2 release**.
   - The probe is an **injectable coordinator** following the **exact discipline** of the Story 9.1 `AuditChainVerificationCoordinator` and Story 9.2 `AuditCompletenessMeasurer`: a **pure evaluator** + a **fail-closed** signal path, **no always-on `BackgroundService`** (the periodic Dapr-timer/`PeriodicTimer` trigger is deferred per the established inert-control-floor pattern — build + test the evaluator, coordinator, and alert path fully; a scheduler need only call the sweep method on its cadence).
   - **Fail-closed (Epic 8/9 no-fabrication doctrine):** a sweep that cannot complete (store enumeration throws) is itself a **breach signal** (`Unknown`), never a silent pass. Any production-tenant outbound-trace record carrying a non-null `ReplayRunId` is a **stop-ship / M2-gating defect**.
   - **Two complementary assertions** (both required): (a) **outbound-trace store**: no production tenant's outbound-trace store contains a record with a non-null `ReplayRunId`; (b) **audit chain** (defense in depth, reuses `IWormAuditStore.EnumerateTenants`/`EnumerateChain`): no production tenant's WORM chain contains a replay-marked envelope (`AuditReplayExclusion.IsReplayEnvelope`). Production-tenant identity for the sweep is `!ReplayTenantPolicy.IsTestTenant(tenantId)`.
   - **Probe-failure = M2 gate.** Surface the breach as a metadata-only operator alert (new `OperatorAlertKind.ReplayIsolationBreach`) via the existing `IOperatorAlertSink`, **and** return a structured breach outcome a CI/release gate can assert against (mirror `AuditChainVerificationOutcome`: tenants swept, breaches, alerted). A passing release requires zero breaches; document the gate wiring in the ADR.

### Cross-cutting requirements that hold for every AC

- **Tenant isolation by construction is the whole security model (NFR9a, NFR69).** Replay is isolated **because it runs under a test tenant**, and every durable store is tenant-partitioned (`IWormAuditStore.EnumerateChain(tenantId)`, projection/idempotency/outbound stores). The test-mode adapter is an **additional** belt-and-braces guard so that even if a replay command somehow reached an outbound send, no external system is contacted. Never weaken tenant partitioning to "make replay work"; replay works *through* it.
- **Metadata-only / no-leak floor (NFR2, NFR42).** Every would-have-sent record, probe result, alert payload, and `replay_run_id` token is an `AuditMetadata`-safe bounded token (ASCII alnum + `.-_:@|`, marker-ban on `secret`/`password`/`bearer`/`token`/`exception`/file-extension sentinels). The outbound-trace store records **no** recipient addresses, subject, or body — only the safe identity tokens already present on `OutboundMailboxSendRequest`. Reuse `OutboundMailboxSendResult.SafeToken`-style discipline / `AuditMetadata.SafeOptionalToken`.
- **Audit two-phase / WORM is untouched (D4, NFR49a).** This story emits audit through the **existing** `AuditEnvelopeFactory` + `IAuditWriter`/`IWormAuditStore` path; it adds **no** new commit-time gate, never mutates the chain, and does not touch the canonical hash (the v2 form already covers `ReplayRunId` — Story 9.2). The nightly probe is a **read** over the chain/trace stores, out-of-band.
- **`ReplayRunId` is structurally un-rewritable.** Like `SurfaceOrigin` (FR85/S7), the marker is set once at the adapter boundary on the immutable submission and travels into the immutable envelope; no downstream stage can forge or strip it. A production path leaves it null **by omission**, not by an active "clear" step.
- **Inert-control-floor honesty.** The replay *driver/runner* surface (a QA/support UI or CLI that initiates a replay run) and the periodic scheduler are **deferred** consistent with Stories 9.1/9.2 — the seams (test-tenant adapter selection, `ReplayRunId` threading, outbound-trace store, isolation probe coordinator + alert + outcome) are the shippable deliverables, fully built and tested. **Say so explicitly in Completion Notes**: what is wired-and-tested vs. what awaits a periodic trigger / a replay-initiation surface. Never let a deferral read as "done."
- **Define-once / reuse — do NOT reinvent.** Consume by reference: `AuditEnvelope.ReplayRunId` + `AuditReplayExclusion` (9.2), `AuditEnvelopeFactory`/`Create` (the single envelope-construction point), `IOutboundMailboxSender` + `OutboundMailboxSendRequest`/`Result` (Epic 6 seam), the `AcceptedCommandDispatcher` send seam, `IWormAuditStore.EnumerateTenants/EnumerateChain`, the `AuditChainVerificationCoordinator`/`AuditCompletenessMeasurer` probe pattern, `IOperatorAlertSink`/`OperatorAlert`/`OperatorAlertKind`, `AuditMetadata` safe-token helpers, and `CommandGatewayServiceCollectionExtensions` DI shape. Do **not** re-derive tenant partitioning, the exclusion predicate, the safe-token rules, or the audit-then-deliver alert path.

Stories 9.1/9.2 built the audit substrate and the *marker* (`ReplayRunId` + v2 hash coverage + `AuditReplayExclusion`); Story 9.3 made the *query exclusion* real. **This story populates the marker for real, isolates the outbound side, and proves the isolation with a nightly probe.** It is mostly *new seams wired into existing extension points* — **reuse, do not reinvent.**
