## What Went Well

- Service-client authorization stayed layered. Keycloak supplies service-account identity, while ChatBot owns grant semantics, command/query scope, surface binding, expiry, revocation, and audit evidence.
- CLI and MCP adapters remained thin. Both construct typed commands and call `IChatBotClient.SubmitAsync` with their surface origin; neither references server gateway stages or local governance internals.
- Safe-denial fidelity improved after review. CLI failures now include catalog-backed metadata and local validation failures are redacted before submission. MCP transport and unexpected failures now route through metadata-only denial formatting.
- MCP read output was corrected to emit governed enum wire names instead of raw integer ordinals, preserving contract readability and version stability for machine clients.
- Story 5.4 added explicit high-risk denial parity coverage across `ui-api`, `cli`, and `mcp` for authentication denial, stale/revoked grants, wrong surface, unknown resource, and tenant mismatch.
- Architecture tests assert adapter boundaries and the current `ModelContextProtocol` package pin.

## Challenges

- Service-client posture had subtle spoofing risk until review forced service-account evidence to override conflicting human-looking actor-type claims.
- Grant identity binding needed an explicit check that authenticated service-client identity matched the grant's service-client ID.
- CLI partial-success and backend problem-details output initially lost important metadata.
- MCP direct invocation and read-result serialization had machine-surface defects that were not obvious from nominal tool invocation.
- The first Epic 5 retrospective and older planning docs captured the original MCP package/transport expectation; current code uses repo-pinned `ModelContextProtocol 1.4.0` and stdio transport.
- Story artifact hygiene still required review pressure. File Lists, Change Logs, and test summaries needed explicit reconciliation after June 10 changes.

## Key Insights

1. Cross-surface parity is a shared-command-spine invariant. Tests verify it, but adapters must be architecturally unable to bypass it.
2. Machine-surface output is a contract. Enum ordinals, generic HTTP buckets, raw transport failures, and missing client actions are parity defects.
3. Exposure metadata is not authorization. MCP's `mcp-exposed` catalog narrows tool availability; server-side grants remain authoritative.
4. Negative parity tests are as important as success parity. Denials must match in category, code, reason, action, redaction visibility, and correlation behavior.
5. Implementation-claim docs need source-backed verification after every epic, especially when stories are re-reviewed after an earlier retrospective.
