### Review Findings

- [ ] [Review][Decision] An abandoned native lease blocks every later attachment in its association workspace — high (blind-hunter+acceptance-auditor+edge-case-hunter). Only the holder's own task can clear an expired native lease, and only when its work is clean (`FolderDomainProcessor.Native.cs:80-95`); every other task's acquire needs `Ready` with no holder (`:96-97`) and gets retryable `native_contention` forever. Two ways to get there: (a) the holder is never retried — for example its content later stops being `Available`, and the adapter returns before any lease call (`FoldersFolderStore.Native.cs:25-27`); (b) a body was uploaded but never published (the gateway submit failed after the upload) and the lease expired, so the SDK quiesce is never ready and even the same task cannot recover (asserted by `ExpiredAcquireRecoveryCannotClearStagedWorkOrTakeAnotherTask`). Folders has no expiry recorder or operator discard for any lock: no handler emits `LockLeaseExpired` or `OperatorDiscardRequested`, so legacy locks share the gap. Options: 1) defer to the owner C6 reconciliation/operator-discard capability and keep the native binding unwired until it exists; 2) let another task recover a clean expired native holder, reusing the same-task branch and the SDK quiesce (changes the approved E3 rule "another task rejects recovery"; case b stays open); 3) option 2 plus an SDK abandon path for staged bodies of an expired task (new SDK capability).
- [ ] [Review][Patch] Native-task rejections poison the Folders permission worker [references/Hexalith.Folders/src/Hexalith.Folders.Workers/FoldersRejectedCommandClassifier.cs:16] — high (edge-case-hunter). Every `ChangeNativeTask` rejection (routine `native_contention`, `AppendConflict`) is persisted as `FolderCommandRejected` with that command type (`FolderDomainProcessor.cs:1615-1660`). `FoldersFolderPermissionEventProcessor.cs:100-101` calls `FoldersRejectedCommandClassifier.IsOrganization`, which throws "Folders rejection command type is unknown.", and the worker endpoint returns 500 (`FoldersWorkersModule.cs:205-212`) before the operational-status and semantic processors run.
