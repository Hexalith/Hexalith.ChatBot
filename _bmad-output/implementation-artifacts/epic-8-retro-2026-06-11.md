## What Went Well

- The fail-safe/no-fabrication doctrine from Stories 8.1-8.5 carried into runtime activation. Unknown, unavailable, stale, and unmeasurable states remain explicit instead of being presented as healthy.
- Hosted Dapr Workflow binding landed without changing the lifecycle authority. EventStore remains the source of truth, while Dapr Workflow coordinates the correction-propagation saga.
- Story 8.7a replaced the live server control/rate-limit defaults with projection-backed providers and added architecture guard coverage against silent re-inerting.
- Story 8.7b consolidated the deferred runtime callers into one owned periodic enforcement runtime instead of scattering independent background timers.
- Review feedback produced material fixes: 8.7a fixed cross-dimension clobber that could have re-activated disabled subjects, and 8.7b fixed runbook-sampler cadence/evidence issues.
- Metadata-only posture stayed consistent across metrics, alerts, runbook evidence, health endpoints, workflow diagnostics, and operator signals.
- The previous retro's biggest action item was not lost. It became Stories 8.7a/8.7b and was implemented.

## Challenges

- The first Epic 8 retrospective was overtaken by later scope changes. It accurately recorded deferred runtime debt for Stories 8.1-8.5, but it became stale after 8.6/8.7a/8.7b landed.
- Runtime activation remained partial by subject class. The server-side service-client, AI-actor, command-capability, and outbound-channel seams are live; mailbox-source enforcement still lacks a hosted worker path consuming `GovernedControlStateView`.
- Audit projection lag remains no-fabrication/no-reading rather than fully measured. `CheckpointBackedAuditProjectionLagSource` exists, but the only registered checkpoint source still returns no checkpoints because projection committed/projected positions are not exposed.
- Story evidence still needed review correction around File Lists and comments. That issue is smaller than earlier epics but still recurring.
- Some documentation became stale in both directions: older docs said runtime activation was expected but missing; later implementation made that statement false while leaving important caveats.

## Key Insights

1. Deferred-runtime debt needs a named owner. Once the work became Stories 8.7a/8.7b, the team could validate, review, and close it.
2. Runtime activation is more than replacing DI defaults. It requires projection freshness, periodic caller ownership, negative-path tests, health/status evidence, and anti-regression tests.
3. "Live" must be scoped by path. Server gateway seams are active; mailbox worker enforcement and audit-lag checkpoint publication still have explicit gaps.
4. Hosted workflow coordination can improve production readiness without moving lifecycle ownership away from EventStore.
5. Retrospectives can become stale when an epic continues after the retro artifact. Re-runs should preserve the old artifact and add an evidence-based update.
