## Epic Review

Epic 1 is complete from a story perspective. Sprint status shows 21 of 21 Epic 1 stories marked `done`; Epic 2 remains backlog. The aggregate `epic-1` status still said `in-progress` before this retrospective, but every child story was complete, so the retrospective treated Epic 1 as complete and corrected the aggregate tracking status.

Epic 1 delivered the non-negotiable M0 safety floor:

- Buildable Hexalith.ChatBot module with root submodule policy, central package management, CI, release config, Aspire, DAPR, Keycloak, EventStore, Tenants, Server, Client, Contracts, UI, and mirrored tests.
- OpenAPI contract spine, generated typed client, and `IChatBotCommand` adapter contract.
- `CommandGateway` admission spine with authentication, tenant binding, authorization, risk and approval seams, coarse idempotency, fail-closed audit gate, EventStore dispatch, projection, and post-commit audit.
- First real governed command, `RecordGovernedNote`, visible through the UI and carrying immutable surface-origin attribution.
- Architecture fitness tests, differential conformance harness, cross-tenant isolation harness, tenant-scoped fixture and evaluation scaffold.
- UI foundation for semantic tokens, governed primitives, interaction guardrails, responsive/touch behavior, accessibility, live regions, localization, off-surface redaction, recovery patterns, and cognitive-load rules.

## What Went Well

- The command-spine value proof survived review hardening. Story 1.9 started with over-optimistic claims, but review pressure converted it into a real EventStore execute-publish-project path with a Tier-3 opt-in test that inspects durable state instead of only HTTP acceptance.
- Reviews materially improved quality. Senior and adversarial reviews repeatedly found stale story records, false confidence, vacuous tests, missing file-list entries, and boundary gaps; most were auto-fixed and validated.
- Test architecture became a product asset. The architecture, conformance, isolation, fixture, UI contract, and E2E/static fixture lanes now encode the safety floor before Epic 2 starts feature work.
- UI safety foundations were built as reusable contracts instead of one-off page behavior. Later S1/S2/S3 feature surfaces inherit localization, accessibility, redaction, responsive, live-region, and recovery behavior.
- The project avoided recursive submodule behavior and kept the root-only submodule policy mechanically tested.

## Challenges

- Live topology reality was harder than the planning docs described. The implementation had to discover several concrete Aspire/DAPR constraints: EventStore actor state needs the canonical component name `statestore`; the ChatBot read model uses a separate `chatbot-statestore`; pub/sub must be real Redis, not an in-memory per-sidecar default; `localhost` was unsafe on dual-stack hosts; and DAPR service invocation required proxyless endpoints so sidecars dial the real app listener.
- DAPR access control has a local-vs-production distinction. The production posture remains deny-by-default in `accesscontrol.yaml`, but the self-hosted Aspire Tier-3 topology runs with mTLS disabled, so it needs `accesscontrol.local.yaml` to allow the EventStore-to-ChatBot round trip locally.
- Story records occasionally drifted from implementation truth. Several stories needed review fixes to reconcile File Lists, test counts, status claims, and obsolete review conclusions.
- Default `dotnet test` is unreliable in this sandbox because VSTest opens a socket that is denied. The team standardized on compiled xUnit v3 binaries for validation evidence in this environment.
- M0 lifecycle scope changed in practice. `Skipped` became part of the Epic 1 canonical lifecycle implementation and tests, even though parts of the PRD still described it as M1 scope.

## Key Lessons

1. Claims about end-to-end safety are not credible unless a test inspects durable end-state, not only accepted responses.
2. Runtime topology details belong in architecture and README documentation as soon as they are learned; otherwise later stories repeat the same discovery work.
3. Local DAPR security posture must be explicitly separated from production posture. A default-allow local config is acceptable only when it is named, documented, and kept out of the production conformance reference.
4. Generated and contract-backed surfaces need hash or oracle checks because hand-inspection misses drift.
5. UI safety requirements are easier to preserve when expressed as contracts and static fixtures before feature screens arrive.

## Significant Discoveries

Significant plan updates are required for documentation, not for Epic 2 product direction:

- The actual Aspire/DAPR topology differs from the earlier shorthand `chatbot-eventstore + chatbot-statestore` description. The implemented topology uses canonical EventStore actor state component `statestore`, ChatBot derived state component `chatbot-statestore`, and real Redis pub/sub component `chatbot-pubsub`.
- The local self-hosted topology cannot use the production deny-by-default DAPR access-control file when mTLS is disabled. It must load `accesscontrol.local.yaml`, while production keeps `accesscontrol.yaml`.
- The lifecycle state `Skipped` is implemented and tested in Epic 1.

No Epic 2 scope rewrite is required before starting story work, but documentation must be reconciled first so Epic 2 developers do not build against stale topology assumptions.
