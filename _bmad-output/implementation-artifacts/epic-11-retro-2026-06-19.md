## What Went Well

- The ADR-first approach in Story 11.1 gave the epic a stable decision spine before platform and host work began.
- Story 11.2 kept the admission hook platform-generic rather than leaking ChatBot-specific governance into EventStore contracts.
- Stories 11.3 and 11.4 used compatibility adapters and anti-regrowth tests, so SDK adoption did not silently break public HTTP behavior.
- Story 11.5 caught a high-impact live-path defect during review: gateway-submitted commands would have been admitted twice on the EventStore-to-`/process` callback. The fix added a protected admission marker and a real dispatch-to-SDK round-trip test.
- Story 11.6 avoided unapproved EventStore submodule changes and recorded the composition limitation explicitly instead of forcing a false `AddEventStoreDomainModule(...)` claim.

## Challenges

- VSTest is repeatedly blocked in this sandbox by TCP socket permission errors. The team compensated by building projects and running xUnit v3 in-process test binaries directly.
- EventStore standalone `.slnx` verification from the ChatBot super-repo is blocked by intentionally uninitialized nested submodules. The accepted evidence path is the root super-repo build plus EventStore project-level validation unless working in the EventStore standalone checkout.
- The original Story 11.5 parity tests did not exercise the real gateway-to-EventStore-to-SDK callback path. Review exposed that gap and forced stronger evidence.
- `AddEventStoreDomainModule(...)` does not yet express ChatBot's dedicated `chatbot-statestore`, `chatbot-workflow-statestore`, and `chatbot-pubsub` topology. Story 11.6 therefore retained AppHost-local Dapr wiring inside the ADR exception boundary.
- Documentation lagged behind the implementation once `.Aspire` and `.ServiceDefaults` were removed and DataProtection deployment boundaries were added.

## Key Learnings

1. SDK migration needs live-path tests, not only structural and direct-router tests.
2. "Move to platform composition" must be verified against the platform API's actual expressive power. If the SDK lacks a capability, record the gap or add platform work with approval.
3. Review follow-ups should become regression tests immediately when they expose a real production-path risk.
4. Story files need clear distinction between exact required commands and sandbox-equivalent evidence paths.
5. Architecture docs should be updated when an exception boundary is exercised, not only when the target architecture is chosen.
