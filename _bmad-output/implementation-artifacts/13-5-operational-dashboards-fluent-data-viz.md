# Story 13.5: Operational dashboards — real Fluent data visualization

## Story

As an operator using the ChatBot governed UI,
I want `/operational-dashboards` to render its health/queue data through a real Fluent data grid plus status/KPI tiles (`FluentCard`) instead of two stacked monospace `<dl class="chatbot-definition-list">` label-row dumps,
so that the M2 operational surface reads as a designed observability dashboard (not debug output), the **last** `DefinitionListAllowlist` entry is removed (the Epic 13 allowlists all reach empty), and the stable status enumeration + degraded-dependency states + governed read-only semantics are preserved **exactly**.

## Context

`/operational-dashboards` (`OperationalDashboards.razor`, the Story 8.1/8.3/8.5 S8/S10 read-only operability surface) is the **single remaining** page-owned surface in the Epic 12/13 remediation. Story 13.4 (done) migrated 23 `<dl>` surfaces and Story 13.6 (done) migrated the compliance-audit page, deliberately leaving this file's **two** `<dl class="chatbot-definition-list">` dumps for this story. At HEAD `0f3bfc8` the Story 13.1 guard's `DefinitionListAllowlist` holds **exactly one** entry — `Components/Pages/OperationalDashboards.razor` — and every other layout-composition list (`PageHeaderChromeAllowlist`, `PageContentBoxAllowlist`, `CommandBarAllowlist`, `NotYetComposedPageBacklog`) is already `[]`. **This story migrates the data viz, empties that last entry, and brings all five Epic 13 allowlists to empty**, so Story 13.8 can verify "allowlist is empty" and Story 13.9 re-verifies the real render. [Source: `_bmad-output/planning-artifacts/epics.md#Story 13.5`; `sprint-change-proposal-2026-06-22.md#Section 4` (row 13.5); `tests/Hexalith.ChatBot.UI.Tests/ChatBotLayoutCompositionConformanceTests.cs` (lines 84-93); `13-4-migrate-definition-lists-to-fluent-data.md`; `13-6-compliance-audit-form-fluent-grid.md`]

Unlike Stories 13.4/13.6 (which used structured `FluentStack` to preserve `data-*`/`role` markers on fixed key-value metadata), **Story 13.5 is the explicit "real data visualization" story**: the epic AC and `architecture.md#Frontend Architecture` (line 411) name `FluentDataGrid` **plus** status/KPI tiles (`FluentCard`). The two `<dl>` surfaces are genuinely **tabular/repeated** data (one row per observability view; one row per published SLO), which is exactly what `FluentDataGrid` is for. The Story 13.4 review explicitly deferred grid-style data-viz here ("grid-style data-viz is revisited by Story 13.5"). Reference implementation: `Hexalith.Tenants.UI` `TenantAuditPage.razor` + `Components/Tenants/Audit/AuditDataGrid.razor` (the canonical `FluentDataGrid` + `TemplateColumn`/`FluentBadge` + sibling row-marker pattern), guarded by `DomainUiFluentConformanceTests`.

**13.5 is a rendering-layer correction only.** No backend / CommandGateway / query / CLI / MCP / SignalR / Dapr / EventStore / sibling-submodule change. The Fluxor state, the `GetOperationalDashboard` read query, the `OperationalDashboardOverview`/`OperationalDashboardView`/`PublishedSlo` contracts, and the validator are **untouched** — this is markup only. Governed read-only "not a chat transcript" semantics, NFR6 a11y labels/landmarks, UX-DR4 non-color status cues, EN+FR localization, UX-DR34 focus, and the "no fake/freeform textbox" safety model are preserved **exactly**.
