# Story 9.11: Continuity drill and RPO/RTO validation

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an operations owner,
I want continuity drills to validate recovery targets,
so that RPO/RTO assumptions are proven under representative outages rather than assumed.

## Acceptance Criteria

1. **A continuity drill executes recovery from a simulated EventStore outage and a simulated M365 subscription failure, measures recovery against RPO ≤ 15 min and RTO ≤ 4 hr, and recalibrates the [ASSUMPTION] targets per A10 (NFR56).**
   **Given** the recoverable data classes (source records, attachments, approvals, command history, policy snapshots, and audit records),
   **When** the M2 continuity drill runs for a scenario,
   **Then** the drill executes a recovery for each of the two required scenarios — a **simulated EventStore outage** (`eventstore-outage`) and a **simulated M365 subscription failure** (`m365-subscription-failure`) — and the pure `ContinuityDrillEvaluator` compares the **measured RPO** against `RecoveryTargets.MaxRpo` (15 min) and the **measured RTO** against `RecoveryTargets.MaxRto` (4 hr), returning a `ContinuityDrillVerdicts` token (`met` / `missed` / `unmeasurable`). The two targets are the **single source of truth** for the A10/NFR56 [ASSUMPTION] values — defined once on `RecoveryTargets`, never re-typed.
   - **`RecoveryTargets` is the one canonical home for the RPO/RTO targets** (mirror `AuditCompletenessMeasurement.CompletenessTargetFraction`/`RollingWindow`): `public static readonly TimeSpan MaxRpo = TimeSpan.FromMinutes(15);` and `public static readonly TimeSpan MaxRto = TimeSpan.FromHours(4);`, each XML-doc'd as the A10 [ASSUMPTION] target pending drill recalibration (NFR56). Never hard-code `15`/`4` anywhere else.
   - **Closed scenario set.** Add `internal static class ContinuityDrillScenarios` (static `const` members + `All` `IReadOnlySet<string>` + `Contains`, mirroring the closed-set discipline of `ReplayTenantPolicy` constants): `EventStoreOutage = "eventstore-outage"`, `M365SubscriptionFailure = "m365-subscription-failure"`. Both NFR56 scenarios are required; the drill **sweep** runs both. An unknown/unsafe scenario token biases to `unmeasurable` (fail-safe), never a fabricated `met`.
   - **The drill is by construction a test-tenant operation (no production mutation).** Like replay (Story 9.4), a drill runs against a **test tenant** resolved by the single authoritative `ReplayTenantPolicy.IsTestTenant` predicate; it mutates **no** production-tenant durable state. The coordinator must **assert** (not assume) that no production-tenant WORM chain / projection grows during a drill run — every durable store is already tenant-partitioned by construction (NFR9a), so the drill lands only in the test tenant's partition. **Do not** add a "drill flag on a production tenant."
   - **Fail-safe over fabrication (Epic 8/9 no-fabrication doctrine).** A drill that **cannot complete** — the scenario runner throws, recovery never finishes, or measured durations are unavailable — yields `unmeasurable` (a breach signal), **never** a fabricated `met`/100%. Mirror `AuditCompletenessMeasurement.Unmeasurable(...)` and `ReplayIsolationStatus.Unknown` exactly.

2. **No cross-tenant leakage and no unauthorized state mutation occur during or after recovery (NFR59).**
   **Given** the continuity drill,
   **When** recovery runs and completes,
   **Then** the drill produces **no cross-tenant read or write** and **no unauthorized state mutation**: recovery is tenant-scoped to the drill's test tenant by construction (NFR9a/NFR59); the drill report, the operator alert payload, and every emitted token are metadata-only safe bounded tokens that carry **no** foreign-tenant identity, raw item content, recipient PII, prompt, or payload.
   - **Reuse the cross-tenant leakage harness — do NOT build a new no-leak path.** Extend the `CrossTenantLeakageScanner` / `CrossTenantLeakageCorpus` conformance suite (Story 1.12) to assert no foreign-tenant sentinel survives serialization of `ContinuityDrillReport`, the `ContinuityDrillOutcome`, and the `ContinuityDrillTargetMissed` audit envelope / operator alert. **Use a neutral, non-sentinel tenant token** (e.g. `tenant-continuity-drill`) — `tenant-alpha` is the Story 1.12 corpus `BoundTenant` sentinel and `tenant-beta` the `ForeignTenant` (the 9.8/9.9/9.10 leakage-scan gotcha).
   - **No unauthorized state mutation.** The drill is a system/Worker-origin recovery exercise, not a governed command; it performs no governed write outside its test tenant. The coordinator asserts the production-tenant stores are unchanged across a drill run (the Story 9.4 "no production project state mutated" assertion is the template).

3. **A drill report (scenario, start/end, measured RPO/RTO, data-loss check, deviations) is produced as the A10 recalibration evidence artifact (NFR56, A10).**
   **Given** a drill completes,
   **When** it is recorded,
   **Then** the run produces a metadata-only `ContinuityDrillReport` carrying: the `Scenario` (a `ContinuityDrillScenarios` token), `StartedAtUtc` / `EndedAtUtc`, the `MeasuredRpo` and `MeasuredRto` (`TimeSpan`), a `DataLossDetected` boolean (the data-loss check), the `Verdict` (`ContinuityDrillVerdicts` token), a bounded `Deviations` list (safe reason tokens), a `RecalibrationFlag`, an optional `FollowUpActionRef`, the test-tenant `TenantRef`, the `CorrelationId`, and a `ReasonCode`. This report **is** the A10 recalibration evidence artifact.
   - **The data-loss check is part of the verdict (RPO semantics).** RPO is the bound on tolerable data loss; the drill compares the set of operations committed to the WORM chain (the source of truth — D4 fail-open-then-reconcile: the event log is authoritative and the chain is rebuilt from it on recovery) **before** the simulated outage against the set reconstructable **after** recovery. Any committed-before-outage operation missing after recovery sets `DataLossDetected = true`, which forces a non-`met` verdict (it is an RPO violation), and the missing-operation count/locator is a bounded `Deviations` entry. The deep deterministic projection-rebuild equivalence proof is **Story 9.12's** scope — 9.11 owns the drill/measurement/report/data-loss-check; cross-reference 9.12 and do not duplicate its rebuild-equivalence assertion here.
   - **Report shape mirrors `AuditCompletenessMeasurement`** (the closest "measurement + fail-safe" twin): a sealed record of safe bounded tokens with reason-code constants (`DrillCompletedReasonCode = "continuity_drill_completed"`, `DrillUnmeasurableReasonCode = "continuity_drill_unmeasurable"`), an `IsBreach`/`IsMiss` fold, and a static `Unmeasurable(scenario, tenantRef, correlationId, startedAtUtc, endedAtUtc)` factory for a drill that could not complete.

4. **When a drill misses RPO or RTO, the deviation is logged, the [ASSUMPTION] target is flagged for recalibration, and a follow-up action is recorded (A10).**
   **Given** a drill measures a `MeasuredRpo > RecoveryTargets.MaxRpo`, a `MeasuredRto > RecoveryTargets.MaxRto`, or `DataLossDetected == true`,
   **When** the verdict is computed,
   **Then** the `ContinuityDrillEvaluator` returns `missed`, the report records the specific deviation(s) as bounded `Deviations` reason tokens (`rpo_exceeded` / `rto_exceeded` / `data_loss_detected`), sets `RecalibrationFlag = true`, and records a `FollowUpActionRef`; the coordinator then does **fail-closed audit-then-deliver** — it writes the `AuditEnvelopeFactory.ContinuityDrillTargetMissed` pre-commit envelope **before** emitting exactly one `OperatorAlertKind.ContinuityDrillTargetMissed` alert through the existing `IOperatorAlertSink`.
   - **A miss is NOT a silent stop-ship, and NOT a silent pass.** Per A10 the RPO/RTO values are [ASSUMPTION] targets to be **recalibrated** by the drill — a miss is a *recorded deviation that flags recalibration and records a follow-up*, distinct from an isolation-probe breach (Story 9.4/9.5) where zero breaches is stop-ship. The structured `ContinuityDrillOutcome` distinguishes `Met` / `Missed` / `Unmeasurable` so a release/CI gate can assert on the dimension it cares about (e.g. drills *ran and produced evidence* — `Unmeasurable == 0` — vs. all targets met). **An `unmeasurable` drill is the fail-safe breach** (drill could not produce evidence); a `missed` drill is honest evidence that the target needs recalibration. Never collapse `missed` into `met`, and never collapse `unmeasurable` into `met`.
   - **Recalibration is recorded, not silently auto-applied.** `RecalibrationFlag = true` + the `FollowUpActionRef` make the recalibration obligation explicit and auditable; the actual edit of the architecture/PRD [ASSUMPTION] A10 marker (NFR56) is a documented human/ADR follow-up captured in the ADR's recalibration-procedure section, **not** a value the drill code mutates at runtime.

### Cross-cutting requirements that hold for every AC

- **This is a validation-harness story, not a governed-command story.** It is the direct sibling of the Story 9.2 completeness measurer and the Story 9.4/9.5 isolation probes — a **pure evaluator + an injectable coordinator + a structured outcome + fail-closed audit-then-deliver + a metadata-only report**, all server-internal in `.Server/Audit/`. There is **no** `IChatBotCommand`, **no** `ChatBotSpineCommandAllowlist` entry, **no** `ParticipantAuthorizationStage` gating block, and **no** `.Contracts` change. Do not add any of those — copying the 9.7–9.10 governed-command shape here is the primary anti-pattern to avoid.
- **Inert-control-floor honesty (the defining constraint — say it explicitly in Completion Notes).** What ships and is fully built+tested: the `RecoveryTargets`, the `ContinuityDrillScenarios`/`ContinuityDrillVerdicts` token sets, the pure `ContinuityDrillEvaluator`, the `ContinuityDrillReport` artifact, the `ContinuityDrillCoordinator` (run-scenario + sweep, fail-closed audit-then-alert, deviation/follow-up recording, test-tenant-by-construction, no-production-mutation assertion), the `ContinuityDrillOutcome` gate contract, the new `OperatorAlertKind.ContinuityDrillTargetMissed`, and the `AuditEnvelopeFactory.ContinuityDrillTargetMissed` envelope. **Deferred** (documented seams, exactly like Story 9.4's deferred replay driver and 9.1/9.2/9.4/9.5's deferred periodic scheduler): (a) the **live fault-injection runtime** that actually downs a real EventStore / lapses a real M365 Graph subscription against a deployed AKS/Aspire environment — modeled behind an `IContinuityDrillScenarioRunner` seam that the coordinator consumes (tests drive it with a deterministic scripted fake returning measured RPO/RTO + data-loss); (b) the periodic scheduler / release-gate wiring (no always-on `BackgroundService`). The evaluator, coordinator, report, alert path, and gate outcome are real and tested; only the live infra fault-injection and the periodic trigger are deferred. **Never let a deferral read as "recovery is unproven/unmeasured"** — the drill harness, the measurement semantics, the data-loss check, and the fail-closed evidence path are all real and tested against the scenario-runner seam.
- **Fail-safe / no-fabrication floor (Epic 8/9 spine doctrine).** Prefer `unmeasurable` over a fabricated `met`. A drill whose scenario runner throws, whose recovery never completes, or whose durations are unavailable is `unmeasurable` (a breach signal that fail-closed-audits-then-alerts), never a silent pass. Mirror `AuditCompletenessMeasurer` (`Unknown`/unmeasurable, never invented 100%) and `AuditChainVerificationCoordinator` (incomplete → breach).
- **Metadata-only / no-leak floor (NFR2, NFR42, NFR45).** Every report field, outcome field, deviation token, alert payload, follow-up ref, and scenario/verdict token is an `AuditMetadata`-safe bounded token (ASCII alnum + `.-_:@|`, marker-ban on `secret`/`password`/`bearer`/`token`/`exception`/file-extension sentinels). The report records **no** raw email content, recipient addresses, subject, body, prompts, or payloads — only safe tokens, durations, counts, and bounded reason codes. Reuse `AuditMetadata.SafeOptionalToken` / `IsSafeStableIdentifier` for any locator. Metric/alert dimensions stay low-cardinality (`tenant` + bounded `scenario`/`reason` only — never ids/correlation in a metric tag).
- **Read-mostly / out-of-band — the commit path is untouched (D4, two-phase audit, NFR15a).** The drill exercises recovery and reads the WORM chain / projections out-of-band; it adds **no** commit-time gate and never mutates the audit chain. Its only writes are (i) into the **test tenant's** partition during recovery exercise, and (ii) the fail-closed `ContinuityDrillTargetMissed` pre-commit audit envelope on a miss/unmeasurable. The WORM chain is the source of truth and is rebuilt from the event log on recovery (D4) — the drill validates that property, it does not weaken it.
- **Deterministic, pure evaluation.** `ContinuityDrillEvaluator.Evaluate(...)` is pure and deterministic (no clock, no IO inside; `ISystemClock` only at the coordinator edges for timestamps). Re-running the evaluator over the same measured inputs yields the same verdict.
- **Tenant isolation by construction (NFR9a, NFR59).** Recovery is isolated **because the drill runs under a test tenant** and every durable store is tenant-partitioned (`IWormAuditStore.EnumerateChain(tenantId)`, projection/idempotency stores). Never weaken partitioning to "make the drill work"; the drill works *through* it. The production-tenant identity for the no-mutation assertion is `!ReplayTenantPolicy.IsTestTenant(tenantId)`.
- **Boundary (NetArchTest-enforced).** All new types are `internal` to `.Server` (`ContinuityDrillEvaluator`, `ContinuityDrillCoordinator`, `ContinuityDrillReport`, `ContinuityDrillOutcome`, `ContinuityDrillScenarios`, `ContinuityDrillVerdicts`, `RecoveryTargets`, `IContinuityDrillScenarioRunner`). No `.Contracts`/`.UI`/`.Cli`/`.Mcp` reference. Confirm `DependencyDirectionFitnessTests` / `AdapterBoundaryFitnessTests` stay green.
