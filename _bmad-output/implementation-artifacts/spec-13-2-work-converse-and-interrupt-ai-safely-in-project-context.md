## Intent

**Problem:** The conversation route cannot safely deliver Story 13.2: healthy reads render degraded, secured UI calls lack the contributor token, cancellation targets the wrong aggregate and treats a request as terminal, synchronous AI execution is not stoppable, history/project switches lose authoritative state, and browser tests skip the real workflow.

**Approach:** Complete one conversation-centric, event-sourced lifecycle from authenticated UI admission through asynchronous AI execution, cancellation confirmation, typed projection refresh, accessible rendering, and real-route acceptance evidence.

## Boundaries & Constraints

**Always:** Authorize tenant/project before access; derive risk/authority server-side; persist lifecycle only through EventStore; treat SignalR as a metadata-only requery nudge; preserve Fluent V5, EN/FR, focus/live regions, redaction, exact concurrency, and warnings-as-errors.

**Ask First:** Any breaking public contract, identity-provider claim/client redesign beyond the existing `hexalith-chatbot` OIDC client, or change required inside a sibling submodule.

**Never:** Edit the dirty EventStore/Tenants submodules; add direct persistence; trust client risk/tenant/actor claims; project a cancellation request as completed; ship fabricated project choices; clear drafts before admission; or claim acceptance from source scans, `SetContentAsync`, screenshots, or a diagnostic fallback alone.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Workspace | no project, empty, active, switch, history | Correct state; newest truth stays visible; older items merge without forced scroll | Opaque denial; degradation keeps the last safe same-project view |
| Submit | Message/Ask-AI, including version `0` | Authenticated admission; risky AI becomes proposal; draft clears after acceptance | Blank focuses validation; rejection preserves draft and safe action |
| Stop | active exact identity/version | Aggregate records Cancelling; executor confirmation becomes stopped | Wrong/stale/terminal/duplicate targets fail closed/no-op without fake success |
| Race/recovery | completion race, duplicate nudge, reconnect, late load | Typed requery wins; natural completion is not announced stopped; focus returns once | Stale responses cannot overwrite newer state; reconnect rebuilds/rejoins |
| Presentation | EN/FR; supported widths/modes | Attribution, redaction, status, action, focus, announcements remain usable | No color/motion-only meaning or clipped critical action |

## Design Notes

Use the started progress conversation id as the shared aggregate identity while retaining an explicit compatibility path for already-persisted state-owning streams, Started events, work indexes, and cursors. Record the authoritative EventStore stream version on every applied transition; Message/proposal/approval/Stop compare against that current version, while provider/terminal snapshots bind all identity, requester, context, policy, evidence, and correlation fields to persisted Started truth. A persisted Started event/outbox signal—not a gateway submit receipt—owns provider scheduling. Executor terminal commands require a protected internal admission marker that an authenticated contributor cannot manufacture.

Production must fail startup unless the DAPR-backed work store is enabled; process-local storage is Testing/Development-only. The coordinator uses canonical collision-free identity encoding, stable ULID terminal ids, unioned legacy/current indexes, bounded rotating reads, constant-bounded insertion, terminal compaction, and quarantine that removes/suppresses poisoned sources. Leases fence commits; provider calls that ignore cancellation cannot retain scheduler slots forever. A terminal relay remains pending until persisted truth is observed. Exhausted work is discoverable and recoverable through authenticated operator operations. Cancellation moves Active to Cancelling; cancellation failure restores the same active/runnable identity in aggregate, work, and projection; observed cancellation alone confirms stopped; persisted natural completion beats a racing Stop; and provider approval remains proposal-gated.

Every UI effect carries its request id and project id, plus accepted command/item and generation identity when applicable; a project switch invalidates all old-scope identities, and effects recheck scope before every delayed poll or dispatch. Submit verification waits for the admitted item itself. Cancellation verification derives a bounded deadline from the server lease/recovery policy (or additive projection metadata), preserves correlation through that window, and cannot overwrite a newer generation/project. Authoritative coverage or tombstones purge omissions inside the covered interval—including an all-covering empty result—while retaining rollover outside it. History failures do not disable the composer. SignalR stores only authoritative reload watermarks, obtains current circuit-scoped tokens, and recreates closed/exhausted connections. Production fails startup for absent, partial, malformed, or non-HTTP(S) OIDC configuration. Treat the stateful fake route as supporting proof only; production acceptance keeps the real client, authentication, CommandGateway, EventStore, and SignalR path and runs as a required zero-skip CI/release lane.

Review-loop 4 invariants refine those rules: persisted Started/work truth carries both the logical conversation and exact state-owner aggregate plus the applied event version. Every owner-guarded store operation reports success; an expired/lost owner cannot renew, mutate, or relay. Provider invocations occupy independently replenished, deadline-bounded slots, and legacy/current duplicates collapse before execution. Durable indexes validate encoded and stored identity, spill bounded capacity safely, paginate all operator-visible exhausted work, and quarantine overflow/corruption without replay failure. Projection CAS retries recompute merges from the winning value, and coverage is keyed to a contiguous owner stream rather than a numerically overlapping global interval.

Switching projects clears every old-scope busy flag and receipt as well as correlation ids. Reconnect actions are scope-gated, and a closed or failed-rejoin hub schedules its own bounded rebuild. Submission verification matches the admitted command/item; Stop uses the generation's explicit state owner and version. Additive coverage metadata retains the existing public constructor/deconstruction surface unless the human explicitly approves a breaking contract. The required real-route matrix asserts every critical surface in every row, while focused tests force lease theft, noncooperative/hung providers, migration duplication, index saturation, concurrent projection writes, mixed-stream coverage, and stale project/hub callbacks.
