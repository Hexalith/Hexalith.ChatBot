## What Went Well

- The guard-first sequence worked. Story 12.1 made the raw-control and CSS-primitive debt measurable, shrink-only, and build-blocking before migration started.
- Migration stories kept scope disciplined. Stories 12.2-12.7 changed UI rendering and focused tests without changing backend, CommandGateway, CLI, MCP, SignalR, package pins, or sibling submodule source.
- The team preserved governed semantics while changing component primitives. Story records repeatedly verified stable ids, `aria-*`, `data-chatbot-*`, redaction markers, metadata-only audit content, disabled reasons, live-region behavior, and EN/FR localization.
- Story 12.8 completed the main architecture correction: `chatbot.tokens.css` no longer functions as a parallel design system. It now contains Fluent-backed semantic aliases plus layout/accessibility hooks.
- Story 12.9 produced broad release evidence: UI, E2E, conformance, CLI, MCP, architecture, source scans, and build checks all passed, with the full UI.E2E suite running through the real browser path.

## Challenges

- VSTest remained blocked in this sandbox by socket permission errors. The team used compiled xUnit v3 runners and documented the environment limitation.
- Browser fallback paths repeatedly hid real regressions until senior review forced live Chromium execution. This appeared in Stories 12.4, 12.5, 12.6, 12.7, 12.8, and evidence correction in 12.9.
- Fluent custom elements required browser-specific fixes that source fixtures could not prove, including exact accessible-label matching, number-input value propagation, and custom-element visibility/fill behavior.
- CSS retirement removed native-control styling that had been carrying hidden behavior and touch-target sizing. Review found and fixed the `[hidden]` display regression and touch-target collapse.
- Planning shorthand named Fluent APIs that did not exist in the pinned RC (`FluentTextField`, `FluentNumberField`, `FluentSearch`) or implied a `FluentDataGrid` rewrite that the locked semantic row contracts did not support.

## Key Learnings

1. Guard-first remediation is effective when the guard is non-vacuous, exact, and shrink-only.
2. Browser-path evidence is mandatory for Fluent custom-element work. String fixtures are useful fallback evidence, but they are not sufficient when Chrome is available.
3. Accessibility can live in CSS by accident. Removing primitive CSS must include checks for hidden state, focus visibility, touch target size, reduced motion, and forced-colors behavior.
4. Pinned RC component names must be verified against installed package APIs, not inferred from planning shorthand or external examples.
5. Semantic markup should not be rewritten only to look more "componentized." The audit timeline and dashboard row contracts stayed semantic because those roles were the safer accessibility and test contract.
