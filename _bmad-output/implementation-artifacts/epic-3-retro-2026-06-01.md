## What Went Well

- The S1 conversation model grew incrementally without bypassing the contract spine. Each story extended DTOs, OpenAPI, generated client, server projection, UI service/state, and UI/E2E coverage where needed.
- Redaction and metadata-only behavior stayed central. Reviews caught restricted attachment size leakage, policy/audit ID exposure, raw failure metadata, unsafe provenance fallbacks, and unavailable-state ambiguity before the stories were marked done.
- Projection ordering and replay safety improved materially. Story reviews fixed stale source-email enrichment, DAPR approval re-enrichment, retry-state collapse, stale/corrected attachment capture eligibility, superseded terminal safety states, and latest-policy selection for AI-context packaging.
- UI accessibility and localization kept pace with new conversation states. Reviews added unique why-panel landmark labels, localized signal/failure/decision/classification labels, live-region deduplication, and explicit redacted/unavailable explanations.
- Attachment and AI-context work ended with a concrete Epic 4 handoff: the system can expose an auditable context-package manifest before any model/tool invocation.

## Challenges

- Stable wire tokens remained a recurring risk. Decision/correction metadata, blocked-state values, review-history entries, and status facets each needed review fixes to preserve wire tokens rather than CLR enum names or generic display labels.
- Projection handlers were easy to under-wire. Story 3.8 implemented and tested `AiOutcomeProjectionHandler` directly before review found it was not registered or mapped as a DAPR endpoint.
- Redaction needed defense in depth across projection, service, UI, and fixture expectations. Several fixes were not single-line projection changes; they required contract/client/UI/static/E2E assertions so tests could not bless restricted metadata.
- Attachment lifecycle semantics were more subtle than simple capture/storage. Eligibility had to account for current association state, stale/superseded outcomes, safety scan order, tenant unsafe-handling policy, and hiding stored references after later unsafe outcomes.
- The local validation environment still blocks VSTest socket creation. The reliable path remains solution build plus compiled xUnit v3 executables, with existing Tier-3 Docker/DAPR gates skipped unless the environment opts in.

## Key Insights

1. S1 is a governed read projection, not a chat transcript. It must preserve source evidence, decisions, status, review history, and redaction state without inventing facts.
2. Conversation projection correctness depends on source-version ordering and explicit re-enrichment paths for out-of-order DAPR delivery.
3. Redacted, unavailable, unknown, unsafe, failed, and retryable are distinct user and security states; collapsing them creates both UX and compliance defects.
4. AI provenance must never be fabricated from actor identity. Missing model/version metadata should become a safe unavailable token.
5. Attachment capture is policy-governed lifecycle orchestration. Capture, storage, scan, authorization, and AI eligibility must advance independently but materialize coherently.
6. Epic 4 should consume Story 3.14's context-package manifest directly; it should not reselect files or infer authorization outside the package assembler.

## Significant Discoveries

- The implemented S1 conversation path is ChatBot-owned. Architecture still described `Hexalith.Conversations`/`Adapters/Conversations`, but the code has `IProjectConversationProjectionStore`, `DaprProjectConversationProjectionStore`, contract query records, UI ProjectConversation state/service/components, and no `Adapters/Conversations` implementation.
- Story 3.8 showed that direct handler tests are insufficient unless DI registration and DAPR endpoint mapping are also verified.
- Story 3.11 showed that AI-summary provenance must use explicit model/version metadata or a safe unavailable token; actor identity is not model provenance.
- Story 3.12 and 3.13 showed that attachment safety can retroactively affect displayed storage references, so the projection must hide stored file/folder IDs when later safety state blocks exposure.
- Story 3.14 showed that policy snapshot and source evidence must be derived from the latest authorized/current items, and fabricated fallback evidence must not make a file eligible for AI context.
